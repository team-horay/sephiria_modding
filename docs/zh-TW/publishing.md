# 發布至工作坊

本頁說明如何將模組上傳至 Steam 工作坊、審核系統如何運作，以及多人遊戲中模組如何在玩家之間同步。


## 上傳之前

- 要將模組上傳至工作坊，必須有預覽圖（PNG 或 JPG，小於 1 MB）。透過 `info.preview` 設定，或在模組資料夾中放入 `thumbnail.png`。詳情請參閱 [metadata.json 參考](metadata.md#preview)。
- `info.title` 最多 128 個字元，`info.description` 最多 7999 個字元。如果以多種語言撰寫，工作坊頁面會使用 `en-US` 版本。
- 在 `tags` 中填入工作坊分類。可用的分類請參閱 [metadata.json 參考](metadata.md)。
- 資料夾中的每個檔案都會接受審核，請確認模組資料夾中沒有遊戲 DLL 的副本、`.pdb` 檔案或建置的中間產物。

## 發布步驟

1. 啟動 Sephiria。
2. 在標題畫面開啟 **Steam 工作坊** 面板，找到你製作的模組。
3. 選取你的模組，然後按下**上傳至創意工坊**。
4. 不含程式碼的模組，上傳至工作坊後即完成發布。
5. 含有程式碼（DLL）的模組在上傳至工作坊完成後，會連同工作坊物品 ID 一起自動提交至**審核系統**。
6. 前往已上傳的工作坊頁面，做訂閱等最後測試，然後將可見性改為「公開」。

如果已上傳至工作坊，只有審核提交失敗（例如因為網路錯誤），請對同一個模組再按一次**上傳至創意工坊**。如果內容沒有變更，模組不會再次上傳至工作坊，只會重新傳送提交。提交必須使用建立該工作坊物品的 Steam 帳號進行。

## 程式碼審核

- 審核系統會反編譯 DLL，檢查網路通訊、檔案存取、混淆與惡意行為。審核結合了自動分析與營運人員檢查，我們也明白沒有任何審核系統能攔截所有風險。儘管如此，我們仍希望透過這個審核流程減少惡意模組的散布。感謝你的配合。
- 所有含有程式碼（DLL）的模組**也必須提交至模組審核系統**。為此，請務必使用遊戲內的**上傳至創意工坊**按鈕上傳。
- 已上傳至工作坊但未提交至審核系統的模組，原則上玩家無法執行。
- 下載模組的玩家會使用模組的工作坊物品 ID 與已安裝的 DLL 查詢審核狀態。
  - **已提交 / 已核准**：模組會執行。即使審核尚未完成也會執行。
  - **未提交 / 已駁回**：模組不會執行，並會在模組面板中顯示原因。
- 如果在審核中發現問題，模組即使已發布也可能被駁回。被駁回的模組可以透過面板中的**查看駁回原因**確認原因。被駁回的 DLL 無法原封不動地再次發布；請修正問題後重新上傳。
- 即使沒有 `dll` module，只要有 `libraries`，或含有更改副檔名的 DLL 或 EXE，模組仍需接受審核。
- 需要程式碼審核的模組，其資料夾壓縮後必須在 20 MB 以下。

### 審核失敗原因

|訊息|原因|
|---|---|
|審核系統中沒有提交紀錄。|模組已上傳至工作坊，但未提交至審核系統。請使用**上傳至創意工坊**按鈕重新提交。|
|審核系統已駁回該模組的核准。|營運團隊基於某些原因駁回了該模組。請確認駁回原因。|
|無法從審核伺服器取得資訊。|訂閱者的網路連線可能中斷，或審核伺服器可能發生問題。|
|這是舊審核系統的模組。|審核伺服器已升級，模組原有的驗證資料已被重設。請重新提交。|
|在模組中偵測到未經授權的DLL。|如果模組執行期間模組內的 DLL 檔案組成發生變化，該模組的載入會受到限制。也就是說，以下做法可能違反審核系統：模組在執行時從外部下載 DLL 並載入組件；模組在執行時自行產生並執行 DLL；模組將以自有壓縮方式封裝在內部的 DLL 解壓縮後使用。|

## 可見性與公開

- 首次上傳時，可見性會設為 `Unlisted`（不公開）。
- 公開之前，請先自行訂閱，確認安裝下來的版本運作正常，然後再改為「公開」。
- 頁面說明、截圖、其他語言的說明等，可以在 Steam 工作坊的物品頁面上編輯。

## 更新模組

更新模組的方式與發布時相同。

- 變更了 DLL 的更新會在上傳後自動重新提交，並再次接受審核。如果沒有變更任何 DLL，審核狀態會維持不變。
- 請勿更改 `modId`。否則會被視為不同的模組，可能導致相依性等問題。
- **每次更新都務必提高 `metadata.json` 中的 `version`。** 加入多人遊戲大廳時會比較模組版本，如果內容改了但版本沒改，模組內容不同的玩家可能會進到同一場遊戲而發生問題。

## 上傳票證

上傳後，`uploadticket.json` 會被加入你的模組資料夾。它包含你的工作坊物品 ID 與審核提交資訊，所以**請勿刪除**。如果你用 git 管理模組資料夾，最保險的做法是連這個檔案一起提交。如果更換電腦或重灌系統，你需要這個檔案才能繼續更新同一個工作坊物品。沒有它，遊戲會把資料夾視為從未發布過的新模組。

1.1.1 之前的審核系統所使用的 `mod-guard-manifest.json` 與 `mod-guard.sig.json` 已不再使用。即使仍然留著，也不會被上傳至工作坊，可以刪除。

遺失該檔案時的復原方式請參閱[常見問題](faq.md)。


## 多人遊戲規則

### 多人遊戲大廳設定

房主建立多人遊戲大廳時，**房主已啟用的模組清單**會登錄到大廳。

- `installation` 設為 `host_only` 的模組：參與者不需要安裝；只會顯示在清單中。
- `multiplayer.installation` 設為 `everyone`（或未宣告）的模組：參與者也必須安裝。
- 服裝模組與資料模組：參與者也必須安裝。

### 加入

若玩家目前的模組設定與大廳不同，會經過以下步驟：下載 → 啟用 → 重新啟動遊戲並再次嘗試加入。

### 安裝在 WorkshopLocal 中的測試模組

載入了 `WorkshopLocal/` 本機模組的遊戲無法進行多人遊戲。要測試多人遊戲，請將模組上傳至工作坊、清空本機資料夾，並使用訂閱下來的版本。即使物品為 `Unlisted`（不公開），也可以透過連結訂閱。
