# ワークショップへの公開

このページでは、MODをSteamワークショップにアップロードする方法、審査システムの仕組み、マルチプレイでプレイヤー間のMODがどのように同期されるかを説明します。


## アップロードの前に

- MODをワークショップにアップロードするには、プレビュー画像(PNGまたはJPG、1MB未満)が必須です。`info.preview` で設定するか、MODフォルダに `thumbnail.png` を置いてください。詳細は [metadata.json リファレンス](metadata.md#preview) を参照してください。
- `info.title` は最大128文字、`info.description` は最大7999文字です。複数の言語で書いた場合、ワークショップページには `en-US` のものが使われます。
- ワークショップのカテゴリは `tags` に入れます。使用できるカテゴリは [metadata.json リファレンス](metadata.md) を参照してください。
- フォルダ内のすべてのファイルが審査の対象になるため、MODフォルダにゲームDLLのコピー、`.pdb` ファイル、ビルドの中間出力が含まれていないことを確認してください。

## 公開の手順

1. Sephiriaを起動します。
2. タイトル画面で **Steamワークショップ** パネルを開き、作成したMODを探します。
3. MODを選択します。
4. コード(DLL)を含むMODはコード審査を受けます。
5. コードを含まないMODはすぐにワークショップにアップロードできます。
6. アップロードされたワークショップページに移動し、購読するなどして最終テストを行ってから、公開範囲を「公開」に変更します。

## コード審査

- 審査システムはMODフォルダ内のすべてのファイルを検査します。DLLは逆コンパイルされ、ネットワーク通信、ファイルアクセス、難読化、悪意ある動作がないか確認されます。画像、サウンド、JSONなどのデータファイルは形式が正しいか確認されます。
- 問題が見つからなければMODは自動的に承認され、疑わしい点があれば運営者が手動で確認します。明らかに悪意のあるMODは自動的に却下されます。
- 審査は自動解析と運営者の確認を組み合わせたもので、どんな審査システムでもすべてのリスクを捕捉できるわけではないことは理解しています。それでも、この事前の審査と承認のプロセスを通じて、悪意あるMODの拡散を減らすことを目指しています。ご協力をお願いします。
- MODがコードを含むかどうかは、ファイル名ではなくファイルの**内容**で判定されます。`dll` モジュールがなくても、`libraries` がある場合や、拡張子を変えたDLLやEXEが含まれている場合は審査の対象になります。
- コード審査を受けるMODは、フォルダを圧縮した状態で20MB以下である必要があります。

## 承認証明(コードを含むMODのみ)

- コードを含むMODには承認証明が発行されます。
- MODのファイルが承認されたバージョンと同一であることを証明します。
- DLL MODは、ダウンロードしたプレイヤーがそのコードを実行できるようになる前に、この証明を受ける必要があります。
- 証明後にファイルが1つでも変わると証明は無効になり、MODは再度審査を受ける必要があります。

## 公開範囲と一般公開

- 最初にアップロードした時点では、公開範囲は `Unlisted`(限定公開)に設定されています。
- 一般公開する前に、自分で購読してインストールされたコピーが正しく動作することを確認してから、「公開」に変更してください。
- ページの説明、スクリーンショット、他の言語での説明などは、Steamワークショップのアイテムページから編集できます。

## MODの更新

MODは公開したときと同じ方法で更新できます。

- DLL MODは新しい承認証明が必要です。
- `modId` を変更しないでください。別のMODとして扱われ、依存関係などが壊れることがあります。
- **更新のたびに、必ず `metadata.json` の `version` を上げてください。** マルチプレイのロビーに参加する際にMODのバージョンが比較されるため、内容が変わったのにバージョンが同じままだと、異なる内容のMODを持つプレイヤーが同じゲームに入って問題が起きることがあります。

## アップロードチケット

審査を依頼してアップロードすると、以下のファイルがMODフォルダに追加されます。これらには審査承認の情報が含まれているので、**削除しないでください**。MODフォルダをgitで管理している場合は、この3つのファイルもコミットしておくのが最も安全です。PCを乗り換えたりフォーマットしたりした場合、同じワークショップアイテムを更新し続けるにはこれらのファイルが必要です。

| ファイル | 内容 |
|---|---|
| `uploadticket.json` | 審査チケットとワークショップアイテムID。これがないと、ゲームはそのフォルダを一度も公開されていない新しいMODとして扱います。 |
| `mod-guard-manifest.json`, `mod-guard.sig.json` | 審査の承認証明: 承認されたファイルのリストと署名。編集すると承認が無効になります。 |

これらのファイルを失った場合の復旧方法は [FAQ](faq.md) を参照してください。

## 承認の取り消し

公開後にルール違反が見つかった場合、運営者は承認を取り消すことがあります。取り消されたMODはインストールされていてもロードされず、パネルには「審査承認が取り消されました」と表示されます。


## マルチプレイのルール

### マルチプレイロビーの構成

ホストがマルチプレイのロビーを作成すると、**ホストが有効にしているMODのリスト**がロビーに登録されます。

- `installation` が `host_only` のMOD: 参加者はインストール不要で、リストに表示されるだけです。
- `multiplayer.installation` が `everyone`(または未宣言)のMOD: 参加者もインストールする必要があります。
- コスチュームMODとデータMOD: 参加者もインストールする必要があります。

### 参加

プレイヤーの現在のMOD構成がロビーのものと異なる場合、次の手順を踏みます: ダウンロード → 有効化 → ゲームを再起動して再度参加を試みる。

### WorkshopLocal にインストールしたテスト用MOD

`WorkshopLocal/` のローカルMODがロードされたゲームでは、マルチプレイは利用できません。マルチプレイをテストするには、MODをワークショップにアップロードし、ローカルフォルダを空にして、購読したコピーを使ってください。アイテムが `Unlisted`(限定公開)の状態でも、リンクから購読できます。
