# ワークショップへの公開

このページでは、MODをSteamワークショップにアップロードする方法、審査システムの仕組み、マルチプレイでプレイヤー間のMODがどのように同期されるかを説明します。


## アップロードの前に

- MODをワークショップにアップロードするには、プレビュー画像(PNGまたはJPG、1MB未満)が必須です。`info.preview` で設定するか、MODフォルダに `thumbnail.png` を置いてください。詳細は [metadata.json リファレンス](metadata.md#preview) を参照してください。
- `info.title` は最大128文字、`info.description` は最大7999文字です。複数の言語で書いた場合、ワークショップページには `en-US` のものが使われます。
- ワークショップのカテゴリは `tags` に入れます。使用できるカテゴリは [metadata.json リファレンス](metadata.md) を参照してください。
- フォルダ内のすべてのファイルが審査の対象になるため、MODフォルダにゲームDLLのコピー、`.pdb` ファイル、ビルドの中間出力が含まれていないことを確認してください。

## 公開の手順

1. Sephiriaを起動します。
2. タイトル画面で **Steamワークショップ** パネルを開き、作成したMODを探します。
3. MODを選択し、**ワークショップにアップロード** を押します。
4. コードを含まないMODは、ワークショップへのアップロードで完了です。
5. コード(DLL)を含むMODは、ワークショップへのアップロードが終わると、ワークショップアイテムIDとともに自動的に**審査システム**に申請されます。
6. アップロードされたワークショップページに移動し、購読するなどして最終テストを行ってから、公開範囲を「公開」に変更します。

ワークショップへのアップロードは終わったのに審査の申請だけが失敗した場合(ネットワークエラーなど)は、同じMODでもう一度 **ワークショップにアップロード** を押してください。内容が変わっていなければワークショップには再アップロードされず、申請だけが再送信されます。申請は、そのワークショップアイテムを作成したSteamアカウントで行う必要があります。

## コード審査

- 審査システムはDLLを逆コンパイルし、ネットワーク通信、ファイルアクセス、難読化、悪意ある動作がないか確認します。審査は自動解析と運営者の確認を組み合わせたもので、どんな審査システムでもすべてのリスクを捕捉できるわけではないことは理解しています。それでも、この審査プロセスを通じて、悪意あるMODの拡散を減らすことを目指しています。ご協力をお願いします。
- コード(DLL)を含むすべてのMODは、**MOD審査システムにも申請する必要があります。** そのため、必ずゲーム内の **ワークショップにアップロード** ボタンでアップロードしてください。
- ワークショップにアップロードされていても審査システムに申請されていないMODは、原則としてプレイヤーが実行できません。
- MODをダウンロードしたプレイヤーは、MODのワークショップアイテムIDとインストールされたDLLを使って審査状態を照会します。
  - **申請済み / 承認**: MODは実行されます。審査が終わる前でも実行されます。
  - **未申請 / 却下**: MODは実行されず、MODパネルに理由が表示されます。
- 審査中に問題が見つかった場合、公開後でもMODが却下されることがあります。却下されたMODは、パネルの **却下理由を確認** で理由を確認できます。却下されたDLLはそのままでは再び公開できません。問題を修正してから再度アップロードしてください。
- `dll` モジュールがなくても、`libraries` がある場合や、拡張子を変えたDLLやEXEが含まれている場合は審査の対象になります。
- コード審査を受けるMODは、フォルダを圧縮した状態で20MB以下である必要があります。

### 審査失敗の理由

|メッセージ|原因|
|---|---|
|審査システムに申請履歴がありません。|MODはワークショップにアップロードされましたが、審査システムに申請されていません。**ワークショップにアップロード** ボタンでもう一度申請してください。|
|審査システムがこのMODの承認を却下しました。|運営チームが何らかの理由でMODを却下しました。却下理由を確認してください。|
|審査サーバーから情報を取得できません。|購読者のインターネット接続が切れているか、審査サーバーに問題がある可能性があります。|
|以前の審査システムのMODです。|審査サーバーがアップグレードされ、MODの既存の検証データがリセットされました。もう一度申請してください。|
|MOD内で許可されていないDLLが検出されました。|MODの実行中にMOD内のDLLファイルの構成が変わると、そのMODのロードが制限されます。つまり、次のようなものは審査システムに違反する可能性があります: 実行中に外部からDLLをダウンロードしてアセンブリをロードするMOD、実行中に独自のDLLを作成して実行するMOD、内部に独自の圧縮方式で格納したDLLを展開して使うMOD。|

## 公開範囲と一般公開

- 最初にアップロードした時点では、公開範囲は `Unlisted`(限定公開)に設定されています。
- 一般公開する前に、自分で購読してインストールされたコピーが正しく動作することを確認してから、「公開」に変更してください。
- ページの説明、スクリーンショット、他の言語での説明などは、Steamワークショップのアイテムページから編集できます。

## MODの更新

MODは公開したときと同じ方法で更新できます。

- DLLを変更した更新は、アップロード後に自動的に再申請され、再度審査を受けます。DLLを変更していなければ、審査状態はそのまま維持されます。
- `modId` を変更しないでください。別のMODとして扱われ、依存関係などが壊れることがあります。
- **更新のたびに、必ず `metadata.json` の `version` を上げてください。** マルチプレイのロビーに参加する際にMODのバージョンが比較されるため、内容が変わったのにバージョンが同じままだと、異なる内容のMODを持つプレイヤーが同じゲームに入って問題が起きることがあります。

## アップロードチケット

アップロードすると、MODフォルダに `uploadticket.json` が追加されます。ワークショップアイテムIDと審査申請の情報が含まれているので、**削除しないでください**。MODフォルダをgitで管理している場合は、このファイルもコミットしておくのが最も安全です。PCを乗り換えたりフォーマットしたりした場合、同じワークショップアイテムを更新し続けるにはこのファイルが必要です。これがないと、ゲームはそのフォルダを一度も公開されていない新しいMODとして扱います。

1.1.1より前の審査システムで使われていた `mod-guard-manifest.json` と `mod-guard.sig.json` は、現在は使われません。残っていてもワークショップにはアップロードされないので、削除して構いません。

このファイルを失った場合の復旧方法は [FAQ](faq.md) を参照してください。


## マルチプレイのルール

### マルチプレイロビーの構成

ホストがマルチプレイのロビーを作成すると、**ホストが有効にしているMODのリスト**がロビーに登録されます。

- `installation` が `host_only` のMOD: 参加者はインストール不要で、リストに表示されるだけです。
- `multiplayer.installation` が `everyone`(または未宣言)のMOD: 参加者もインストールする必要があります。
- コスチュームMODとデータMOD: 参加者もインストールする必要があります。

### 参加

プレイヤーの現在のMOD構成がロビーのものと異なる場合、次の手順を踏みます: ダウンロード → 有効化 → ゲームを再起動して再度参加を試みる。

### WorkshopLocal にインストールしたテスト用MOD

`WorkshopLocal/` のローカルMODがロードされたゲームでは、マルチプレイは利用できません。マルチプレイをテストするには、MODをワークショップにアップロードし、ローカルフォルダを空にして、購読したコピーを使ってください。アイテムが `Unlisted`(限定公開)の状態でも、リンクから購読できます。
