# 창작마당에 올리기

모드를 창작마당에 올리는 방법, 검수 시스템, 멀티플레이 시 플레이어끼리 모드가 동기화되는 방법에 대해 설명합니다.


## 올리기 전에 확인할 것

- 창작마당에 모드를 올리려면 미리보기 이미지(PNG 또는 JPG, 1MB 미만)가 필수입니다. `info.preview`로 지정하거나, 모드 폴더에 `thumbnail.png`를 두세요. 자세한 내용은 [metadata.json 레퍼런스](metadata.md#preview)를 확인하세요.
- `info.title`은 128자, `info.description`은 7999자까지 허용됩니다. 여러 언어로 적었다면 `en-US`가 창작마당 페이지에 올라갑니다.
- `tags`에 창작마당 카테고리를 적습니다. [metadata.json 레퍼런스](metadata.md)에서 사용할 수 있는 카테고리를 확인하세요.
- 폴더 안의 파일이 전부 검수 대상이 되므로, 모드 폴더에 게임 DLL 사본, `.pdb`, 빌드 중간 산출물이 섞여 있지 않은지 확인하세요.

## 게시 절차

1. 세피리아를 실행합니다.
2. 타이틀 화면의 '스팀 창작마당' 패널을 열어 내가 작성한 모드를 확인합니다.
3. 내 모드를 선택하고 **창작마당에 올리기**를 누릅니다.
4. 코드를 포함하지 않는 모드는 창작마당 업로드로 끝납니다.
5. 코드(DLL)가 포함된 모드는 창작마당 업로드가 끝난 뒤, 창작마당 게시글 번호와 함께 자동으로 **검수 시스템**에 접수됩니다.
6. 업로드된 창작마당 페이지로 이동하여, 구독 등 마지막 테스트를 진행한 후 게시 상태를 '공개'로 변경합니다.

창작마당 업로드는 끝났는데 검수 접수만 실패했다면(네트워크 오류 등) 같은 모드에서 **창작마당에 올리기**를 다시 누르세요. 내용이 그대로면 창작마당에 다시 올리지 않고 접수만 다시 보냅니다. 접수는 창작마당 항목을 만든 Steam 계정으로 해야 합니다.

## 코드 검수

- 검수 시스템은 DLL을 디컴파일해 외부 통신, 파일 접근, 난독화, 악성 동작이 있는지 검사합니다. 자동 분석과 운영자 확인으로 이루어지며, 이러한 검수 시스템이 모든 위험을 찾아낼 수는 없음을 이해합니다. 다만 이러한 검수 절차를 통해 악성 모드가 퍼지는 것을 줄이고자 합니다. 여러분의 협조에 감사드립니다.
- 코드(DLL)가 포함된 모든 모드는 **반드시 모드 검수 시스템에 함께 접수되어야 합니다.** 이를 위해서는 반드시 게임의 '창작마당에 올리기' 버튼을 통해 업로드하세요.
- 창작마당에는 업로드 되었지만, 검수 시스템에 접수되지 않은 모드는 유저들이 일반적으로 실행할 수 없습니다.
- 모드를 내려받은 플레이어는 그 모드의 창작마당 번호와 설치된 DLL로 검수 상태를 조회합니다.
  - **접수됨·승인됨**: 실행됩니다. 검수가 끝나기 전에도 실행됩니다.
  - **미접수·반려됨**: 실행되지 않고, 모드 패널에 사유가 표시됩니다.
- 검수 과정에서 문제가 확인되면 이미 게시된 모드라도 반려될 수 있습니다. 반려된 모드는 패널에서 **반려 사유 조회**로 사유를 볼 수 있으며, 반려된 DLL 그대로는 다시 게시할 수 없습니다. 수정한 뒤 다시 올려 주세요.
- `dll` 모듈이 없어도 `libraries`가 있거나 확장자를 바꾼 DLL·EXE가 들어 있으면 검수 대상이 됩니다.
- 코드 검수를 받는 모드는 폴더를 압축한 크기가 20MB 이하여야 합니다.

### 검수 실패 사유

|항목|원인|
|---|---|
|검수 시스템에 접수 이력이 존재하지 않습니다.|창작마당에는 업로드 되었지만 검수 시스템에는 접수되지 않았습니다. '창작마당에 올리기' 버튼을 통해 다시 제출하세요.|
|검수 시스템에서 해당 모드의 승인을 반려했습니다.|모종의 사유로 운영팀에서 해당 모드를 반려한 경우입니다. 반려 사유를 확인하세요.|
|검수 서버로부터 정보를 받아올 수 없습니다.|구독자의 인터넷 연결이 끊겼거나, 검수 서버에 이상이 있을 수 있습니다.|
|이전 검수 시스템의 모드입니다.|검수 서버가 버전업해서 기존 모드의 인증정보가 초기화 되었습니다. 다시 제출하세요.|
|모드 내에 인가받지 않은 dll이 감지되었습니다.|모드 내 dll 파일 목록이 모드 실행 도중 변경되면 해당 모드 로드는 제한됩니다. 즉, 다음 동작은 검수 시스템에 저촉될 수 있습니다. (모드가 실행 도중 외부에서 dll을 다운로드 받아 assembly load 실행, 모드가 실행 도중 자기만의 dll을 생성 및 실행, 본인 모드 안에 본인만의 압축 방식으로 넣어둔 dll을 압축 해제하여 사용)|

## 게시 상태와 공개 전환

- 처음 올리면 게시 상태는 `미등록`으로 만들어집니다.
- 공개 전에 직접 구독하여 설치본이 제대로 동작하는지 확인 후 '공개'로 변경하세요.
- 페이지 설명, 스크린샷, 다른 언어 설명 등은 스팀 창작마당 게시글 페이지에서 수정 가능합니다.

## 모드 업데이트 방법

게시 절차와 동일한 방식으로 모드를 업데이트할 수 있습니다.

- DLL을 바꾼 업데이트는 올린 뒤 자동으로 다시 접수되고 검수를 거칩니다. DLL을 바꾸지 않았다면 검수 상태는 그대로 유지됩니다.
- `modId`는 변경하지 마세요. 다른 모드로 간주되어 의존성 등이 깨질 수 있습니다.
- **업데이트마다 `metadata.json`의 `version`을 반드시 올리세요.** 멀티플레이 로비 입장 시 모드 버전을 비교하므로, 내용이 바뀌었는데 버전이 같으면 서로 다른 내용의 모드로 같은 게임에 들어가게 되어 문제가 생길 수 있습니다.

## 업로드 티켓

업로드를 거치면 모드 폴더에 `uploadticket.json`이 추가됩니다. 창작마당 게시 번호와 검수 접수 정보가 들어 있으므로 **지우지 마세요.** 모드 폴더를 git으로 관리한다면 이 파일도 함께 커밋해 두는 것이 안전합니다. 컴퓨터를 바꾸거나 포맷하면 이 파일이 있어야 같은 창작마당 항목을 이어서 갱신할 수 있습니다. 이 파일이 없으면 게임은 이 폴더를 아직 게시한 적 없는 새 모드로 봅니다.

1.1.1 이전 검수 방식에서 쓰던 `mod-guard-manifest.json`, `mod-guard.sig.json`은 더 이상 쓰이지 않습니다. 남아 있어도 창작마당에는 올라가지 않으며, 지워도 됩니다.

파일을 잃어버렸을 때 복구하는 방법은 [FAQ](faq.md)에 있습니다.


## 멀티플레이 규칙

### 멀티플레이 로비 구성

호스트가 멀티플레이 로비를 만들면 **호스트가 활성화한 모드 목록**이 로비에 함께 등록됩니다.

- `installation`이 `host_only`인 모드:  참가자에게 설치를 요구하지 않고 목록에만 표시됩니다.
- `multiplayer.installation`이 `everyone`(또는 미선언)인 모드: 참가자도 설치가 필요합니다.
- 코스튬 모드와 데이터 모드: 참가자도 설치가 필요합니다.

### 참가

플레이어의 현재 모드 구성과 입장할 로비의 모드 구성이 다르면 '다운로드 → 활성화 → 게임 재시작 후 입장 시도'의 절차를 거칩니다.

### WorkshopLocal에 설치된 테스트 모드

`WorkshopLocal/`의 로컬 모드가 로드된 게임에서는 멀티플레이어가 불가능합니다. 멀티플레이 테스트는 창작마당에 올린 뒤 로컬 폴더를 치우고 구독본으로 하세요. `미등록` 상태에서도 링크로 구독할 수 있습니다.
