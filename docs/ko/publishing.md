# 창작마당에 올리기

모드를 창작마당에 올리는 방법, 검수 형태, 멀티플레이 시 플레이어끼리 모드가 동기화 되는 방법에 대해 설명합니다.


## 게시 절차 한눈에

코드(DLL)가 포함된 모드는 **검수 요청 → 승인 → 증명 받기 → 게시** 네 단계를 거칩니다.

| 단계 | 하는 일 | 버튼 |
|---|---|---|
| 요청 | 모드 폴더를 압축해 검수 서버에 보냅니다. | **검수 요청** |
| 검사 | 서버에서 파일을 검사합니다. | (검수 중) |
| 승인 | 승인된 파일 목록과 서명을 받아 모드 폴더에 저장합니다. | **승인 증명 받기** |
| 게시 | 창작마당에 새 글을 쓰거나 갱신합니다. | **창작마당에 올리기** |

번역·코스튬·데이터처럼 **코드가 없는 모드는 검수 없이** 바로 **창작마당에 올리기**를 누르면 됩니다(게시 규칙 동의 창은 똑같이 뜹니다). 이런 모드에 DLL 같은 실행 파일이 섞여 있으면 확장자와 상관없이 코드가 있는 모드로 보고 검수를 거쳐야 하며, 검수 없이 올라간 경우 다른 사람의 게임이 그 모드를 불러오지 않습니다.


## 1. 올리기 전에 확인할 것

- 창작마당에 모드를 올리기 위해서는 **`thumbnail.png`**(PNG 또는 JPG, 1MB 미만)가 필수로 존재해야 합니다.
- `info.title`은 128자, `info.description`은 7999자까지입니다. 여러 적었다면 `en-US`가 창작마당 페이지에 올라갑니다.
- `tags`에 창작마당 카테고리를 적습니다. [metadata.json 레퍼런스](docs/ko/metadata.md)에서 사용할 수 있는 카테고리를 확인하세요.
- 폴더 안의 파일이 전부 검수 대상이 되므로, 모드 폴더에 게임 DLL 사본, `.pdb`, 빌드 중간 산출물이 섞여 있지 않은지 확인하세요. 
- 모드 폴더 전체를 압축한 크기는 기본적으로 20MB 이하여야 합니다.


## 2. 검수 요청

1. 패널에서 모드를 선택하고 **검수 요청**을 누릅니다.
2. 모드 게시 규칙 동의 창이 뜹니다. 내용은 [README의 규칙](../../README.md#규칙)과 같습니다.
3. 게임이 Steam 계정으로 검수 서버에 로그인하고 모드를 보냅니다. 별도 가입은 없습니다.
4. 보내고 나면 패널 상단에 검수 진행 띠가 생기고, 버튼이 **검수 중**으로 바뀝니다. 게임은 주기적으로 상태를 확인하므로 패널을 열어 두면 됩니다.


### 검수 시스템이 하는 일

- 검수 시스템은 모드 폴더의 모든 파일을 확인합니다. DLL은 디컴파일해 외부 통신, 파일 접근, 난독화, 악성 동작이 있는지 검사하고, 이미지·소리·JSON 같은 데이터 파일은 형식이 올바른지 확인합니다.
- 문제가 없으면 자동으로 승인되고, 의심스러운 부분이 있으면 운영자가 직접 확인합니다. 악성 행위가 분명하면 자동으로 반려됩니다.
- 검수는 자동 분석과 운영자 확인으로 이루어지며, 모든 위험을 찾아낼 수는 없습니다. 검수를 통과했다고 해서 모드가 완전히 안전하다는 뜻은 아닙니다. 사전 검수와 승인 철회로 악성 모드가 퍼지는 것을 최대한 줄이기 위한 조치입니다. 여러분의 협조에 감사드립니다.

### 검수 시스템이 열어볼 수 없는 파일

검수 서버는 모드 폴더 안의 파일을 하나씩 열어 확인합니다. 일반 zip은 안쪽까지 검사하지만, 모드 제작 도구가 만드는 자체 형식 묶음 파일(`.pak`, `.dat` 등)이나 암호화된 파일은 열 수 없습니다. **이런 파일이 있으면 내용을 확인할 수 없어 승인되지 않습니다.** 묶지 않은 상태로 다시 제출해 주세요.

- **파일은 묶거나 암호화하지 말고 모드 폴더에 그대로 두세요.** 실행 코드(DLL)도, 이미지·JSON 같은 데이터도 마찬가지입니다. 폴더에 그대로 있는 파일은 검수 서버가 직접 검사할 수 있어, 문제가 없으면 자동으로 승인됩니다.
- 모드 제작 도구에 "묶음(pack)"이나 "암호화" 배포 옵션이 있다면 끈 상태로 내보내세요.
- 다른 모드가 코드를 추가할 수 있는 확장 모드를 만든다면, 그 코드를 확장 모드가 직접 파일에서 읽어 로드하지 말고 게임 로더에 맡겨 주세요. 추가 코드를 만드는 쪽이 DLL을 자기 모드의 `dll` 모듈로 선언하고 확장 모드를 `dependencies`에 적으면, 게임이 확장 모드를 먼저 로드한 뒤 그 DLL을 로드합니다. 확장 모드는 등록용 API를 제공하거나, 이미 로드된 어셈블리에서 타입을 찾는 방식으로 연결하면 됩니다. 확장 모드가 직접 로드한 코드는 검수를 거치지 않으므로 승인되지 않을 수 있습니다.


## 3. 승인 증명 받기

승인되면 버튼이 **승인 증명 받기**로 바뀝니다. 누르면 검수 서버에서 승인된 파일 목록(`mod-guard-manifest.json`)과 서명(`mod-guard.sig.json`)을 받아 모드 폴더에 저장합니다.

이 두 파일이 "이 폴더의 내용이 승인본과 같다"는 증거입니다. DLL 모드는 이 증명이 있어야만 다른 사람의 게임이 그 DLL을 실행합니다. 증명을 받은 뒤 파일을 하나라도 바꾸면 증명이 무효가 되고 다시 검수를 받아야 합니다.


## 4. 창작마당에 올리기

증명까지 저장되면 버튼이 **창작마당에 올리기**로 바뀝니다.

- **처음 올리면 항목이 Unlisted(링크 공개)로 만들어집니다.** 창작마당 목록에는 보이지 않고 링크를 아는 사람만 볼 수 있습니다. 공개로 바꾸는 것은 창작마당 페이지의 "가시성 변경"에서 직접 합니다. 공개 전에 구독해서 설치본이 제대로 동작하는지, 멀티플레이가 되는지 확인하는 용도입니다.
- 게시된 뒤에는 **창작마당 페이지 열기** 버튼으로 페이지에 갈 수 있습니다. 페이지의 설명, 스크린샷, 다른 언어 설명은 거기서 편집합니다.
- 창작마당 항목 번호는 모드 폴더의 `uploadticket.json`에 기록됩니다. 다음에 올릴 때 이 번호가 있으면 새 항목이 아니라 **같은 항목의 갱신**이 됩니다.


## 5. 업데이트 올리기

모드 파일을 바꾸면 패널 상태가 **제출 뒤 변경됨**으로 바뀌고 버튼이 **다시 검수 요청**이 됩니다. 절차는 처음과 같습니다. 검수 요청 → 승인 → 증명 받기 → 창작마당에 올리기. 마지막 단계에서 기존 항목이 갱신됩니다.

- `metadata.json`의 `version`을 올리세요. 창작마당 변경 내역에 버전이 기록되고, 의존하는 모드가 정확한 버전을 요구할 때 기준이 됩니다.
- 게임 업데이트 뒤 다시 빌드만 하고 내용이 같아 보여도, DLL 바이트가 바뀌면 재검수 대상입니다.
- `modId`는 바꾸지 마세요. 바꾸면 게임이 다른 모드로 봅니다.


## 6. 승인 철회

게시 후에 규칙 위반이 확인되면 운영자가 승인을 철회할 수 있습니다. 철회된 모드는 설치되어 있어도 게임이 로드하지 않고, 패널에 "검수 승인이 철회됨"으로 표시됩니다. 같은 접수를 다시 승인하는 방법은 없고, 고친 뒤 새로 검수를 받아야 합니다.


## 멀티플레이 규칙

### 방 구성

호스트가 방을 만들면 **호스트가 켠 모드 목록**(창작마당 번호와 로드 순서)이 방 정보에 실립니다. 여기 들어가는 모드는 다음입니다.

- `multiplayer.installation`이 `local_only`가 **아닌** 모드 중 DLL 코드가 실행된 것
- 코드 없는 코스튬 모드와 데이터 모듈 모드

번역 전용 모드와 `local_only` 모드는 방 구성에 들어가지 않습니다. 각자 켜고 끄는 것이 자유입니다.

방 목록에서 모드 방은 기본으로 숨겨져 있고, 필터 토글을 켜야 보입니다.

### 참가

모드 방에 들어가려는 사람의 구성이 방과 다르면 참가 대화상자가 뜹니다.

| 상황 | 대화상자 |
|---|---|
| 방에 있는 모드가 내게 없음 | **다운로드 받기** → 구독·다운로드 → 검수 증명 확인 → **재시작 후 입장** |
| 내게만 켜진 모드가 있음 | 실행 중엔 끌 수 없으므로 **재시작 후 입장** |
| 모드는 같은데 로드 순서가 다름 | 호스트 순서를 저장하고 **재시작 후 입장** |
| 호스트가 로컬 모드(`WorkshopLocal/`)를 사용 중 | 받을 방법이 없으므로 참가 불가. 안내만 뜹니다. |

**재시작 후 입장**을 누르면 켠 모드 목록이 방 구성으로 통째로 바뀌고, 게임이 다시 실행된 뒤 타이틀에서 자동으로 그 방에 들어갑니다.

### 제작자가 알아둘 것

- `WorkshopLocal/`의 로컬 모드가 로드된 실행에서는 방을 만들 수 없고 모드 방에 들어갈 수도 없습니다. 멀티플레이 테스트는 창작마당에 올린 뒤 로컬 폴더를 치우고 구독본으로 하세요. Unlisted 상태에서도 링크로 구독할 수 있습니다.
- 창작마당에서 받은 DLL 모드는 **승인 증명이 있어야 로드**됩니다. 제작자가 구독한 자기 모드도 예외가 아닙니다.
- 다른 모드에 의존하는 모드는 그 의존 모드도 방 구성에 들어갑니다. 참가자는 둘 다 구독하게 됩니다.
- `installation`을 `local_only`로 선언했는데 실제로는 공유 상태(아이템, 유닛, 통신)를 건드리면, 방 구성 비교에서 빠진 채 참가자마다 다른 게임을 하게 됩니다. 애매하면 `everyone`으로 두세요.


## 게임이 모드 폴더에 만드는 파일

검수 요청과 업로드를 거치면 모드 폴더에 파일이 자동으로 추가됩니다. 이 파일들에는 당신의 검수 승인 정보가 포함되어 있으므로 **지우지 마세요.** 모드 폴더를 git으로 관리한다면 이 세 파일도 함께 커밋해 두는 것이 안전합니다. 컴퓨터를 바꾸거나 포맷하면 이 파일이 있어야 같은 창작마당 항목을 이어서 갱신할 수 있습니다.

| 파일 | 내용 |
|---|---|
| `uploadticket.json` | 검수 티켓과 창작마당 게시 번호. 이게 없으면 게임은 이 폴더를 아직 게시한 적 없는 새 모드로 봅니다. |
| `mod-guard-manifest.json`, `mod-guard.sig.json` | 검수 승인 증명. 승인된 파일 목록과 서명입니다. 내용을 고치면 승인이 무효가 됩니다. |


## 파일을 잃어버렸을 때

**증명 파일(`mod-guard-manifest.json`, `mod-guard.sig.json`)만 없고 `uploadticket.json`은 남아 있다면** 패널에서 그 모드를 선택하고 **승인 증명 받기** 버튼을 누르면 검수 서버에서 다시 받아 옵니다. 손으로 만들 것은 없습니다.

**포맷 등으로 `uploadticket.json`까지 잃었다면** 게임은 그 폴더를 새 모드로 보기 때문에, 그대로 올리면 기존 글이 갱신되지 않고 새 글이 하나 더 생깁니다. 기존 글을 이어서 갱신하려면 다음 순서로 복구합니다.

1. 창작마당에서 자기 모드를 구독합니다.
2. Steam이 내려받은 폴더(`<Steam 라이브러리>/steamapps/workshop/content/2436940/<창작마당 번호>/`)를 통째로 `WorkshopLocal/` 아래에 복사합니다. 폴더 이름은 아무거나 괜찮습니다.
3. 복사한 폴더에 `uploadticket.json`을 아래 내용으로 만듭니다. 번호는 창작마당 페이지 URL의 `id=` 뒤 숫자입니다.

```json
{
  "modId": "yourname.first-mod",
  "publishedFileId": 123456789
}
```

4. 게임을 실행하면 패널에 "검수 요청 전"으로 보입니다. 검수 요청 → 승인 → 승인 증명 받기 → 창작마당에 올리기를 다시 거치면 **기존 글이 갱신**됩니다.

주의할 점 두 가지입니다.

- 창작마당 번호를 `metadata.json`에 적어도 아무 효과가 없습니다. 게임은 `uploadticket.json`의 번호만 봅니다.
- 다른 모드를 만들려고 기존 모드 폴더를 복제했다면 `uploadticket.json`과 증명 파일을 **반드시 지우세요.** 남겨 두면 새 모드가 원래 모드의 창작마당 글을 덮어씁니다.
