# metadata.json

Файл `metadata.json` в корне папки мода является ключевым файлом, который описывает и **что** представляет собой ваш мод, и **как** он работает.


## Общая структура

```json
{
  "info": {
    "title": "New Artifact Pack",
    "description": "Adds 12 artifacts.",
    "preview": "thumbnail.png"
  },
  "mod": {
    "schemaVersion": 1,
    "modId": "yourname.artifact-pack",
    "version": "0.9.1",
    "author": "Your Name",
    "multiplayer": { "installation": "everyone" },
    "modules": [
      { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" },
      { "type": "localization", "path": "Localization" }
    ],
    "libraries": [
      "bin/Helper.dll"
    ],
    "dependencies": [
      { "modId": "someone.shared-runtime", "version": "2.5.3", "workshopId": "123456789" }
    ]
  },
  "tags": ["Item"]
}
```

На верхнем уровне определяются три вещи.

| Ключ | Роль | Обязательно |
|---|---|---|
| `info` | Название, описание и превью, которые отображаются в Мастерской Steam и во внутриигровой панели | Обязательно |
| `tags` | Теги Мастерской | Необязательно |
| `mod` | Как работает мод | Обязательно |

## info

### title

- Название мода. Если оставить пустым, вместо названия будет использоваться `modId`.
- С помощью языковой карты можно задать название мода для каждого языка.
	- Помимо своего языка, рекомендуем добавить английский.
- Поддерживаемые коды языков: `ko-KR`, `en-US`, `ja-JP`, `zh-CN`, `zh-TW`, `de-DE`, `fr-FR`, `es-ES`, `it-IT`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `th-TH`, `tr-TR`

```json
"info": {
  "title": { "en-US": "New Artifact Pack", "ko-KR": "새 아티팩트 팩" }
}
```

### description

- Описание мода.
- Как и `title`, описание можно задать для каждого языка отдельно.

```json
"info": {
  "description": { "en-US": "Adds 12 artifacts.", "ko-KR": "아티팩트 12종을 추가합니다." }
}
```

### preview

- Для загрузки в Мастерскую требуется изображение превью. (PNG или JPG, менее 1 МБ)
- Укажите относительный путь к изображению превью.
- Если поле не указано, игра ищет в корневой папке файлы `thumbnail.png`, `preview.png`, `thumbnail.jpg` и `preview.jpg` в указанном порядке.


## mod

### schemaVersion

- Текущая версия: 1.
- Учтите, что это число может увеличиться в будущем, если механизм работы модов существенно изменится.

### modId

- Уникальная строка, идентифицирующая ваш мод. Используйте строчные латинские буквы, цифры, точки, дефисы и подчёркивания. До 64 символов.
- **Выберите уникальное имя.** Если ваш `modId` совпадёт с `modId` другого мода, он будет работать некорректно. Префикс с именем автора значительно снижает риск совпадений.
(например, `horay.artifact-pack`)
- **Не меняйте `modId` после публикации.** Другие авторы могут создавать дочерние моды на основе вашего через `dependencies`, и родительский мод они идентифицируют именно по `modId`.


### version

- Строка, определяющая версию мода.
- Именно она сравнивается, когда другой мод требует точную версию через `dependencies.version`.
- **Повышайте версию при каждом обновлении мода.** При входе в многопользовательское лобби игра проверяет, что у хоста и участников одинаковые версии модов. Если изменить содержимое, но оставить ту же версию, игроки с разным содержимым модов могут оказаться в одном лобби, что может привести к сбою синхронизации контента или заблокировать прохождение.
- Рекомендуем использовать тот же формат 1.0.0, что и в игре.

### author

Расскажите всем, кто вы!

### multiplayer / installation

Определяет, должен ли этот мод быть у всех игроков в многопользовательской игре. Допустимые значения:

| Значение | Описание |
|---|---|
| `local_only` | Влияет только на ваш собственный экран и UI (сюда относятся моды локализации и простые UI-моды) |
| `everyone` | У всех в комнате должен быть включён одинаковый мод (сюда относится любой мод, который добавляет или изменяет контент) |
| `host_only` | Мод нужно включить только хосту; на стороне остальных участников работает без изменений (сюда относятся многопользовательские моды, влияющие только на вычисления на стороне сервера) |

Если объявить `installation` как `local_only` или `host_only`, но мод затрагивает контент, который нужен и участникам (регистрация новых предметов или юнитов, сетевые объекты, код, который выполняется и на клиентах участников), игроки в одном лобби могут оказаться в разных играх, либо синхронизация контента может дать сбой и заблокировать нормальное прохождение. Обязательно проверяйте, что на самом деле делает ваш мод.


### modules

- Модули определяют, что делает ваш мод, поэтому это **самый важный раздел**.
- Текущие модули: `localization, dll, costume, data`.
- Как в примере ниже, в одном пакете можно сочетать несколько модулей.
- Если хотя бы один модуль неизвестен, весь пакет помечается как «неподдерживаемый», и мод пропускается при загрузке.

```json
"modules": [
  { "type": "localization", "path": "Localization" },
  { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" },
  { "type": "costume", "path": "Costumes" },
  { "type": "data", "path": "Packs", "consumer": "someone.shared-runtime" }
]
```

#### type: модуль localization

```json
"modules": [
  { "type": "localization", "path": "Localization" }
]
```

- Модуль `localization` предназначен для модов, содержащих языковые файлы.
- В `path` укажите папку, в которой лежат языковые файлы.
- Поместите в папку `path` **JSON-файлы, названные по кодам языков**, например `ko-KR.json` и `en-US.json`. Коды языков и формат файлов, используемые игрой, описаны в разделе [Моды локализации](localization-mods.md).

#### type: модуль dll

```json
"modules": [
  { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" }
]
```

- Модуль `dll` позволяет подключаться к игре с помощью кода на C#.
- В `path` укажите путь к DLL-файлу.
- В `entryClass` укажите полное имя класса точки входа в DLL, включая пространство имён. Игра не ищет точку входа в DLL самостоятельно, поэтому её **необходимо указать**. (Для вложенных классов используйте `Ns.Outer+Inner`.)
- Не используйте один и тот же `entryClass` в двух разных модулях.
- Работает только в сборках Mono.
- Подробности см. в разделе [DLL-моды](dll-mods.md).

#### type: модуль costume

```json
"modules": [
  { "type": "costume", "path": "Costumes" }
]
```

- Позволяет создавать собственные костюмы без написания кода на C#.
- В `path` укажите папку, в которой лежат файлы костюмов.
- В многопользовательской игре мод должен быть установлен у всех.
- Подробности см. в разделе [Моды костюмов](costume-mods.md).


#### type: модуль data

```json
"modules": [
  { "type": "data", "path": "Packs", "consumer": "someone.shared-runtime" }
]
```

- Универсальный модуль данных для модов. В типичных случаях он не нужен; в основном используется для зависимостей между модами.
- `consumer` указывает, какой мод будет использовать этот модуль данных, но обычно его опускают. Если поле не указано, читать эти данные может любой мод из `dependencies`.
- Если у вас несколько родительских модов, а данные предназначены только для одного из них, укажите `modId` этого мода в `consumer`. Это значение также должно присутствовать в `dependencies`.

### libraries

```json
"libraries": [
  "bin/Helper.dll",
  { "path": "bin/Newtonsoft.Json.dll" }
]
```

- Список вспомогательных сборок, на которые ссылается ваш модуль `dll`.
- Игра разрешает ссылки, используя **только объявленные здесь файлы**. Просто положить DLL в папку недостаточно, чтобы она была найдена.
- Элементы могут быть либо строкой, либо объектом `{ "path": "..." }`.
- Каждый элемент должен заканчиваться на `.dll`, и мод будет работать некорректно, если он совпадает с DLL из `modules`.
- Библиотеки не считаются точками входа. Даже если в библиотеке есть класс `WorkshopModBase`, он не будет вызван.

### dependencies

```json
"dependencies": [
  { "modId": "someone.shared-runtime", "version": "2.5.3", "workshopId": "123456789" }
]
```

- Если родительский мод относится к типу «создание контента», дочерний мод может добавлять новый контент на его основе.
- В этом случае зависимость от другого мода можно объявить через `dependencies`.
- Если указан родительский мод, ваш мод не может быть загружен раньше него.
- Если родительский мод отсутствует, отключён или не смог загрузиться, загрузка всех его дочерних модов отменяется.
- У зависимости могут быть следующие три поля.

| Поле | Обязательно | Правило |
|---|---|---|
| `modId` | Да | `modId` мода, на основе которого вы строите свой |
| `version` | Нет | **Используйте только тогда, когда нужна точно совпадающая строка версии.** Если версия отличается, загрузка пропускается, поэтому обычно безопаснее это поле не указывать. |
| `workshopId` | Нет | Позволяет пользователям найти требуемый мод и подписаться на него. |


## tags

- Категории, используемые при загрузке в Мастерскую.
- У мода может быть несколько тегов. (Для мода «всё в одном», который добавляет предметы и костюмы, используйте `"tags": ["Item", "Costume"]`.)

| Категория | Содержание |
|---|---|
| `Item` | Предметы (артефакты, таблички, зелья и т. д.), комбо |
| `Costume` | Костюмы |
| `Weapon` | Оружие |
| `NPC` | Путешественники, торговцы и т. д. |
| `Enemy` | Новые враги, боссы и т. д. |
| `Gameplay` | Изменения игрового процесса |
| `QoL` | Улучшения UI, удобства и доступности |
| `Library` | Среды выполнения, фреймворки, пакеты данных и т. д., от которых зависят другие моды |
| `Localization` | Переводы |

## Правила путей
 
- Пути в `modules[].path`, `libraries` и `info.preview` подчиняются одним и тем же правилам.
- Разрешены только пути относительно папки мода. (Абсолютные пути, буквы дисков и `..` отклоняются.)
- Используйте `/` в качестве разделителя.
- Пути, проходящие через символические ссылки или точки соединения (junction), отклоняются.
- **Регистр должен точно совпадать с реальным именем.** В Windows папка откроется и при написании `localization`, но игра отклонит его как отличающееся от `Localization`. (Это правило обеспечивает одинаковое поведение на Steam Deck (Linux).)
