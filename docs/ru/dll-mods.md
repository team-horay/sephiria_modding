# DLL-моды

DLL-модули позволяют выполнять код на C# внутри игры. Подписывайтесь на события `HorayModAPI`, чтобы подключаться к игрокам, предметам, UI и многому другому.
Этот документ охватывает всё от создания проекта до запуска первой DLL в игре. Полный список событий и функций регистрации см. в [Справочнике API](api/README.md).


## Требования

- [.NET SDK](https://dotnet.microsoft.com/download) 8 или новее
- Редактор для C#


## Создание проекта

Ориентируйтесь на пример [`examples/dll-sample`](../../examples/dll-sample). В этом документе он используется как эталон.

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.1</TargetFramework>
    <LangVersion>9.0</LangVersion>
    <AssemblyName>PhysicalDamagePlus</AssemblyName>
    <RootNamespace>PhysicalDamagePlus</RootNamespace>
    <Nullable>disable</Nullable>
    <ImplicitUsings>disable</ImplicitUsings>
    <GenerateDependencyFile>false</GenerateDependencyFile>
    <AppendTargetFrameworkToOutputPath>false</AppendTargetFrameworkToOutputPath>
    <!-- Папка установки игры. Измените под свою систему или передайте через dotnet build -p:GameDir=... -->
    <GameDir Condition="'$(GameDir)' == ''">C:\Program Files (x86)\Steam\steamapps\common\Sephiria</GameDir>
    <OutDir>$(GameDir)\WorkshopLocal\physical-damage-plus\bin\</OutDir>
  </PropertyGroup>

  <ItemGroup>
    <Reference Include="Assembly-CSharp">
      <HintPath>$(GameDir)\Sephiria_Data\Managed\Assembly-CSharp.dll</HintPath>
      <Private>false</Private>
    </Reference>
    <Reference Include="UnityEngine.CoreModule">
      <HintPath>$(GameDir)\Sephiria_Data\Managed\UnityEngine.CoreModule.dll</HintPath>
      <Private>false</Private>
    </Reference>
    <!-- Таким же образом добавьте Mirror, если работаете с сетевыми объектами вроде PlayerAvatar, UnityEngine.UI, если делаете UI, и 0Harmony, если применяете патчи -->
    <Reference Include="Mirror">
      <HintPath>$(GameDir)\Sephiria_Data\Managed\Mirror.dll</HintPath>
      <Private>false</Private>
    </Reference>
  </ItemGroup>
</Project>
```

1. **Целевая платформа `netstandard2.1`**, версия языка C# 9.
2. **Ссылайтесь на игровые DLL, но не копируйте их.** Направьте ссылки на файлы в `<папка установки игры>/Sephiria_Data/Managed/` и у всех установите `Private=false`. Если игровые DLL попадут в папку мода, одна и та же сборка загрузится дважды, что вызывает трудноуловимые ошибки, а также без нужды добавляет файлы к проверке.
3. `Assembly-CSharp.dll` содержит большую часть кода, на котором работает игра.


## Структура кода


```csharp
using UnityEngine;

namespace PhysicalDamagePlus
{
    public class Entry : WorkshopModBase
    {
        public const int Bonus = 5;

        // Вызывается один раз за процесс. Подписывайтесь на события здесь, и только один раз.
        protected override void OnModLoaded()
        {
            Debug.Log($"[PhysicalDamagePlus] Loaded v{metadata.modVersion} | folder={Context.PackageRoot}");

            HorayModAPI.OnPlayerAvatarSpawnedServerside += HandlePlayerSpawnedServer;
            HorayModAPI.OnPlayerAvatarSpawnedClientside += HandlePlayerSpawnedClient;
        }

        protected override void OnModUnloaded()
        {
            HorayModAPI.OnPlayerAvatarSpawnedServerside -= HandlePlayerSpawnedServer;
            HorayModAPI.OnPlayerAvatarSpawnedClientside -= HandlePlayerSpawnedClient;
        }

        // Вызывается только на хосте (сервере). Изменяйте состояние игры здесь.
        private static void HandlePlayerSpawnedServer(PlayerAvatar player)
        {
            if (player == null)
                return;
            player.AddCustomStat(ECustomStat.PhysicalDamage, Bonus);
        }

        // Вызывается у каждого участника. Значение, добавленное сервером, приходит через синхронизацию.
        private static void HandlePlayerSpawnedClient(PlayerAvatar player)
        {
            if (player == null)
                return;
            Debug.Log($"[PhysicalDamagePlus] PhysicalDamage={player.GetCustomStat(ECustomStat.PhysicalDamage)}");
        }
    }
}
```

```json
"modules": [
  { "type": "dll", "path": "bin/PhysicalDamagePlus.dll", "entryClass": "PhysicalDamagePlus.Entry" }
]
```

### WorkshopModBase

Ваш класс наследует от базового класса следующее.

| Член | Описание |
|---|---|
| `metadata` | `modName`, `modVersion`, `modAuthor`. Заполняется значениями из `metadata.json`. |
| `Context` | `PackageRoot` (абсолютный путь к папке мода), `FileId` (ID элемента Мастерской Steam; для локальных пакетов отдельное значение, которое никогда не совпадает с ID Steam), `Definition` (проверенный манифест), `ResolvePath(relativePath)`. Используйте его для поиска файлов внутри папки мода. Путь установки у каждого пользователя свой, поэтому никогда не прописывайте его жёстко. |
| `GetDataPackages()` | Список пакетов модулей `data`, которые указывают этот мод в качестве `consumer`. Вызывайте после завершения активации (внутри обработчика `OnLoad*Database` или после `OnAllDatabasesReady`). |

`Context` действителен с момента вызова `OnModLoaded`. В конструкторе он ещё равен null.


## Жизненный цикл

DLL-моды активируются, **когда вы начинаете игру и входите в мир**. На титульном экране код ещё не выполняется. Порядок запуска следующий.

1. Загружается сцена мира, и запускается `GameDataLoader`.
2. DLL-модули из плана загрузки загружаются по порядку, создаётся экземпляр каждого класса точки входа, и вызывается `OnModLoaded`.
3. По мере инициализации баз данных одно за другим срабатывают события, такие как `OnLoadItemDatabase` и `OnLoadUnitDatabase`.
4. Когда всё готово, вызывается `OnAllDatabasesReady`.

## Подписка на события

Класс `HorayModAPI` предоставляет предопределённые события, которые позволяют подключаться к множеству ситуаций.

- Подписывайтесь на события **только один раз**, в `OnModLoaded`. События баз данных срабатывают заново при каждой загрузке, поэтому то, что «должно происходить каждый раз» (регистрация предметов и т. п.), делайте внутри обработчиков.
- Внимательно управляйте подпиской и отпиской. Отписывайтесь (-=) от событий, на которые подписались, в `OnModUnloaded`.

Полный список событий находится в [Справочнике API](api/README.md). В таблице ниже приведено рекомендуемое событие для каждой задачи.

| Что вы хотите сделать | Событие |
|---|---|
| Добавить предметы или артефакты | `OnLoadItemDatabase` |
| Добавить оружие, чудеса, пассивные навыки, костюмы или пропсы | `OnLoadWeaponDatabase`, `OnLoadMiracleDatabase`, `OnLoadPassiveDatabase`, `OnLoadCostumeDatabase`, `OnLoadPropDatabase` |
| Добавить вражеских или NPC-юнитов | `OnLoadUnitDatabase` + `RegisterNetworkPrefab(prefab, stableKey)` |
| Добавить путешественников (NPC деревни) | `OnLoadSocialIDDatabase` |
| Добавить отображение характеристики | `OnLoadSpecialStatDatabase` + `RegisterSpecialStat` |
| Зарегистрировать локализованный текст из кода | `OnLocalizationReady` (`AddText`) |
| Добавить кнопку в меню титульного экрана | `OnTitleMenuReady` |
| Начало игры или сессии | `OnStartGameServerside/Clientside`, `OnStartSessionServerside/Clientside` |
| При генерации этажа | `OnFloorAllocatedServerside/Clientside`, `OnAssignRoomSpawnPhases` |
| Появление игрока или юнита | `OnPlayerAvatarSpawned*`, `OnUnitSpawnedServerside`, `OnUnitDespawnedServerside` |
| Подключиться к боевым проверкам | `OnPlayerEvade`, `OnGetDebuff` |
| Разрешения на изменение инвентаря | `GridInventoryStartPermission`, `GridInventoryEndPermission` |


## Как избежать конфликтов

Сущности, добавляемые вашим модом, именуются в формате `<modId>:<id>`, например `yourname.artifact-pack:flame-ring`. Это правило предотвращает конфликты с другими модами, и именно так контент модов различается в истории забегов и статистике.


## Серверная сторона, клиентская сторона

- Sephiria построена вокруг многопользовательской игры, поэтому многие события существуют в отдельных серверной и клиентской версиях.
- Хост запускает обе; остальные участники запускают только версию Clientside.
- Как правило, всё, что меняет состояние игры (спавн, дроп, урон), делайте только в Serverside, а всё, что меняет только отображение, в Clientside.


## Патчи Harmony

Когда нужно изменить то, до чего события не дотягиваются, можно использовать Harmony.
Начиная с патча 1.1.0 **Harmony 2.4.3 встроена** в игру, поэтому достаточно добавить на неё ссылку.

```xml
<Reference Include="0Harmony">
  <HintPath>$(GameDir)\Sephiria_Data\Managed\0Harmony.dll</HintPath>
  <Private>false</Private>
</Reference>
```

```csharp
protected override void OnModLoaded()
{
    var harmony = new HarmonyLib.Harmony("yourname.first-mod");
    harmony.PatchAll();
}
```

- **Не включайте `0Harmony.dll` в состав мода.** Вложенная копия игнорируется, а если вы положите другую версию, ваш мод на ней всё равно не запустится.
- Используйте свой `modId` как есть в качестве ID Harmony, чтобы он не совпадал с другими.
- Патчи ломаются при обновлениях игры гораздо чаще, чем официальный API. Делайте всё возможное через события, а патчи оставьте на крайний случай.
- Внешние загрузчики, такие как BepInEx и MelonLoader, не поддерживаются. Мод, работающий как внешний загрузчик (то есть находящий и запускающий DLL плагинов вне Мастерской), получает предупреждение и включается только после того, как пользователь с ним согласится. Подробнее см. в разделе [Моды, выполняющие код вне Мастерской](#моды-выполняющие-код-вне-мастерской).


## Вспомогательные DLL

Если ваш мод использует другие библиотеки (например, сторонние пакеты, кроме Newtonsoft.Json), положите их DLL в папку мода и объявите в `libraries` файла `metadata.json`. Необъявленные DLL не используются при разрешении ссылок.

```json
"libraries": [ "bin/MyHelper.dll" ]
```

- Не включайте DLL, которые уже поставляются с игрой (Unity, Mirror, Newtonsoft.Json, 0Harmony и т. д.). Копия игры загружается первой, поэтому копия из вашего мода либо игнорируется, либо конфликтует.
- Нативные (C/C++) DLL использовать нельзя. Загружаются только управляемые сборки.
- Если сборка с тем же именем уже загружена другим модом, то для DLL из `modules` игра не выбирает одну из двух, а **откладывает запуск**. Для DLL из `libraries` игра использует уже загруженную сборку, а вашу копию игнорирует, из-за чего при различии версий всё может работать неправильно. Безопаснее вынести общие библиотеки в отдельный мод и связать его через `dependencies`.

### Использование библиотеки другого мода

Если несколько модов используют один и тот же код, поместите этот код в один родительский мод, а дочерние моды свяжите с ним через `dependencies`.

1. Родительский мод объявляет общий код в `modules` или `libraries` и добавляет `Library` в свои `tags`.
2. Дочерний мод указывает `modId` родительского мода в `dependencies` и собирается со ссылкой на DLL родительского мода с `Private=false`. **Не копируйте DLL родительского мода в дочерний мод.**
3. Игра сначала загружает родительский мод, поэтому ссылки дочернего мода разрешаются в уже загруженную сборку родительского мода.

```json
"dependencies": [
  { "modId": "someone.shared-runtime", "workshopId": "123456789" }
]
```

- Дочерний мод всё равно должен иметь собственный модуль `dll` и `entryClass`. Схема, в которой родительский мод сам ищет и загружает DLL дочернего, не поддерживается. Вместо этого пусть дочерний мод вызывает функцию регистрации родительского мода из собственного `OnModLoaded`.
- Если родительский мод в обновлении изменит свои открытые типы или члены, дочерние моды могут перестать работать. Не удаляйте и не меняйте существующие открытые API в общей библиотеке.

### Не создавайте DLL во время работы!

Весь код, который выполняет мод, должен находиться внутри проверенного элемента Мастерской. Если DLL-файлы мода меняются во время его работы, загрузка этого мода ограничивается. Включайте все DLL в элемент Мастерской как есть, без какого-либо сжатия или потоковой загрузки. Иными словами, следующие действия могут нарушать требования системы проверки. Кладите все нужные DLL в мод при загрузке.

- Мод во время работы скачивает DLL извне и загружает сборку
- Мод во время работы сам создаёт и запускает DLL (включая переписывание другой DLL с помощью Mono.Cecil и подобных средств с последующим запуском)
- Мод извлекает упакованную в нём DLL собственным способом сжатия и использует её

### Моды, выполняющие код вне Мастерской

Мод, который находит и запускает DLL, положенные пользователем **вне папки мода**, например в папку установки игры или в `AppData` (скажем, мод совместимости с плагинами другого загрузчика), не отклоняется, но система проверки добавляет к нему **предупреждение**.

- Когда пользователь включает такой мод, появляется предупреждение, и мод включается только при согласии пользователя. При обновлении мода вопрос задаётся снова.
- Внешние DLL, запускаемые таким образом, не проходят проверку, а проблемы, которые они вызывают, не поддерживаются.
- Если мод сам скачивает такие DLL во время работы, это подпадает под запреты, указанные выше.

Чтобы использовать код другого мода, не загружайте DLL напрямую из папки этого мода, а свяжите его через `dependencies`, как описано в разделе [Использование библиотеки другого мода](#использование-библиотеки-другого-мода). DLL, которые игра не загружала сама, обходят порядок загрузки, проверку конфликтов имён и проверку зависимостей, поэтому не поддерживаются.

Если DLL нужно переписать (например, преобразовать IL под другой API Harmony), сделайте это до загрузки и включите в мод уже преобразованную DLL.


## Сборка и тестирование

```bash
dotnet build -c Release
```

- Когда сборка пройдёт успешно и DLL появится в `WorkshopLocal/<мод>/bin/`, запустите игру, убедитесь, что ваш мод отображается в разделе «Мои моды» панели Мастерской Steam на титульном экране, и затем начните игру.
- Если оставить `.pdb` рядом с результатом сборки, трассировки стека в логе будут содержать номера строк. При публикации его не включайте.


## Обновления игры и совместимость

При обновлении игры меняется `Assembly-CSharp.dll`. Моды, использующие только официальные события, обычно продолжают работать, но моды, которые напрямую обращаются к внутренним классам или применяют патчи Harmony, могут сломаться.

- После обновления пересоберите мод с новой папкой `Managed/` и протестируйте.
- Если указать **поддерживаемую версию игры** в описании на странице Мастерской, пользователи смогут быстро найти причину проблемы. Версия игры также может автоматически записываться в метаданные элемента Мастерской при публикации.
- Если вы изменили код, его нужно снова отправить в систему проверки. См. [Публикация в Мастерской](publishing.md#проверка-кода).


## Особенности многопользовательской игры

- У большинства модов с кодом `multiplayer.installation` будет равен `everyone`.
- Если ваш мод меняет состояние игры только в событиях `Serverside`, а изменяемые значения являются уже синхронизируемым состоянием игры (например, `customStats`), так что участникам не нужен ни код, ни регистрация, его можно объявить как `host_only`. Тогда участники не скачивают мод. Мод, который регистрирует новые предметы, использует `RegisterNetworkPrefab` или меняет что-либо в событиях `Clientside`, не может быть `host_only`.
- Объекты, создаваемые по сети (юниты, снаряды и т. д.), должны быть зарегистрированы через `RegisterNetworkPrefab`, чтобы создаваться и на стороне участников. Если передать `stableKey`, тот же ID сохранится даже при изменении версии мода.
- У хоста и участников должен совпадать даже **порядок загрузки** модов. Избегайте кода, результат которого зависит от этого порядка.


## Сетевая синхронизация (SyncVar, RPC, Command)

Многопользовательский режим Sephiria реализован на открытой сетевой библиотеке «Mirror». В Mirror сетевыми возможностями можно легко пользоваться, объявляя следующие атрибуты.

- `[SyncVar]`: атрибут для переменной-члена класса. Синхронизирует значение переменной между сервером и клиентами.
- `[ClientRpc]`, `[TargetRpc]`: атрибуты для функции. Сервер просит клиентов выполнить функцию.
- `[Command]`: атрибут для функции. Клиент просит сервер выполнить функцию.

В среде модов эти атрибуты нормально использовать нельзя. Они работают только тогда, когда при компиляции кода Weaver из Mirror вставляет транспортный код, соответствующий каждому атрибуту, а DLL, собранные снаружи, через Weaver не проходят, поэтому даже при успешной сборке эти атрибуты не выполняют никакой функции. Такая ошибка на экране хоста выглядит нормально, а проблемы возникают только на экране участника, поэтому в одиночном тесте её трудно обнаружить. (Даже если принудительно пропустить DLL через Weaver, возможны ошибки, например коллизии хэшей функций.)


### `SyncVar<T>`, `ModRpc`

Чтобы решить эту проблему, Sephiria предоставляет сетевой код для модов, заменяющий эти атрибуты: `SyncVar<T>` и `ModRpc`.

| Что нужно сделать | Что использовать |
|---|---|
| Постоянно поддерживать значение синхронным (включая участников, которые вошли позже) | `SyncVar<T>` |
| Вызов с сервера на всех клиентов | `ModRpc.Send` |
| Вызов с сервера на конкретного клиента | `ModRpc.SendTo` |
| Вызов с клиента на сервер | `ModRpc.SendCommand` |
| Изменить значение, которое игра уже синхронизирует | Свойство `Network<FieldName>` |

- Эта возможность доступна начиная с версии игры 1.1.2.
- Моды, использующие эту возможность, должны объявлять `multiplayer.installation` как `everyone`.


### Подготовка компонента

`SyncVar<T>` и `ModRpc` можно использовать только в компонентах, унаследованных от `NetworkBehaviour`. Этот компонент должен быть прикреплён к одному и тому же объекту и у хоста, и у участника, причём **в одном и том же порядке**. Компонент, добавленный через `AddComponent` к уже заспавненному объекту, в синхронизацию не попадает, поэтому он должен быть прикреплён до регистрации объекта как сетевого префаба.

```csharp
private static GameObject prefab;

// Подпишитесь на HorayModAPI.OnAllDatabasesReady в OnModLoaded.
private static void RegisterPrefab()
{
    if (prefab) return;

    // Поместите под неактивного родителя. Awake префаба не выполняется, а клон, созданный через Instantiate, стартует активным.
    var holder = new GameObject("MyMod_Prefabs");
    holder.SetActive(false);
    Object.DontDestroyOnLoad(holder);

    prefab = new GameObject("FlameOrb");
    prefab.transform.SetParent(holder.transform);
    prefab.AddComponent<NetworkIdentity>();
    prefab.AddComponent<FlameOrb>();
    HorayModAPI.RegisterNetworkPrefab(prefab, "yourname.my-mod:flame-orb");
}

// Спавн на сервере. Если передать второй аргумент, этот игрок станет владельцем.
private static void SpawnFor(PlayerAvatar player)
{
    var orb = Object.Instantiate(prefab);
    NetworkServer.Spawn(orb, player.connectionToClient);
}
```

### `SyncVar<T>`: синхронизация значений

```csharp
public class FlameOrb : NetworkBehaviour
{
    public readonly SyncVar<int> stack = new SyncVar<int>(0);

    public FlameOrb()
    {
        // Weaver отсутствует, поэтому регистрируйте вручную в конструкторе. Порядок полей всегда должен быть одинаковым.
        InitSyncObject(stack);
    }

    private void Awake()
    {
        stack.Callback += (oldValue, newValue) => UpdateVisual(newValue);
    }

    private void UpdateVisual(int value) { }
}
```

- Значение меняйте **на сервере**, например `stack.Value = 3`. Значение, изменённое участником, на сервер не передаётся.
- Участник, который вошёл позже, тоже получает текущее значение при входе.
- `Callback` вызывается у хоста при присвоении значения, а у участника при получении значения. Если значение, полученное при входе, отличается от значения по умолчанию, он вызывается и в этом случае. Исключение, возникшее в колбэке, записывается в лог, а синхронизация продолжается.
- Можно использовать базовые типы, такие как `int`, `float`, `string`, `Vector3`. Код сериализации для struct, созданных модом, автоматически не генерируется, поэтому разбивайте их на отдельные поля.
- Чтобы сослаться на другой объект, вместо `SyncVar<GameObject>` передавайте его `netId` через `SyncVar<uint>`. На принимающей стороне этот объект может быть ещё не создан.
- На одном компоненте можно зарегистрировать не более 64 таких объектов, считая унаследованные.

### `ModRpc`: вызов функций

Функцию нужно один раз зарегистрировать при загрузке мода. При вызове её имя записывается как `modId:functionName`.

```csharp
protected override void OnModLoaded()
{
    ModRpc.RegisterRpc<FlameOrb>("yourname.my-mod", "explode", (orb, r) => orb.PlayExplosion(r.ReadVector3()));
    ModRpc.RegisterCommand<FlameOrb>("yourname.my-mod", "ignite", (orb, r, sender) => orb.ServerIgnite(r.ReadInt(), sender));
}
```

```csharp
// Сервер → все клиенты, которые видят этот объект
ModRpc.Send(this, "yourname.my-mod:explode", w => w.WriteVector3(position));

// Сервер → один клиент. Если вместо соединения передать null, отправка идёт владельцу объекта.
ModRpc.SendTo(connectionToClient, this, "yourname.my-mod:explode", w => w.WriteVector3(position));

// Клиент → сервер
ModRpc.SendCommand(this, "yourname.my-mod:ignite", w => w.WriteInt(slot));
```

- Читайте в том же порядке, в котором писали. Если порядок или типы при записи и чтении различаются, значения будут искажены или возникнет исключение.
- `RegisterCommand` по умолчанию может вызывать **только владелец объекта**. Чтобы принимать вызовы на объекте без владельца, передайте `requiresAuthority: false`. В этом случае вызвать его может любой участник. Помните о читерстве и подобных рисках.
- Если отправить в направлении, отличном от зарегистрированного, или отправить незарегистрированное имя, в лог попадёт только сообщение об ошибке, а отправки не будет.
- Если на принимающей стороне нет функции или тип компонента отличается, в лог пишется только предупреждение, а вызов игнорируется. Исключение в обработчике тоже записывается в лог, и игра продолжает работу.
- Канал по умолчанию использует надёжную передачу. Для часто отправляемых эффектов можно передать аргумент `channelId: Channels.Unreliable`.

### Обязательные правила

- Клиент может отправить через Command произвольные значения. Проверяйте номер слота, количество, цель и т. п. в серверном обработчике.
- Участник, который вошёл позже, не получает RPC, отправленные до его входа. Состояние, которое нужно сохранять, передавайте через `SyncVar<T>`, а RPC используйте для мимолётных событий, таких как звуки и эффекты.
- **RPC может прийти раньше SyncVar.** Если читать `stack.Value` в обработчике RPC, можно получить прежнее значение. Если нужно новое значение, передайте его вместе с аргументами RPC или обработайте в `Callback`.

### Изменение значений в базовом коде Sephiria

Прямое присваивание полю `[SyncVar]` игрового класса участникам не передаётся. Используйте свойство с приставкой `Network`. Регистр совпадает с именем поля.

```csharp
unit.maxHp = 500;         // Меняется только значение у хоста.
unit.NetworkmaxHp = 500;  // Передаётся и участникам.
```

До спавна объекта (у префаба или сразу после `Instantiate`) прямое присваивание тоже работает: значение передаётся вместе с объектом при спавне.

### Тестирование

Хост в одиночку этих проблем не обнаружит. Перед публикацией проверьте экраны и хоста, и участника на двух компьютерах и протестируйте в том числе случай, когда участник входит позже, после изменения значения. Если включить локальный пакет (`WorkshopLocal`), другие люди не смогут войти в комнату, поэтому мультиплеерные тесты проводите, подписавшись на элемент, загруженный в Мастерскую со статусом Unlisted. Первый загруженный элемент автоматически получает статус Unlisted.


## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| В сводке состояния сказано, что класс точки входа не найден | Пространство имён или имя класса в `entryClass` не совпадает с кодом. Вложенные классы записываются как `Outer+Inner`. |
| В сводке состояния ошибка типа класса точки входа | Класс точки входа не наследуется от `WorkshopModBase` (или `HorayModBase`), не является public, является abstract или не имеет публичного конструктора без параметров. |
| В сводке состояния сказано, что мод отложен из-за конфликта имён сборок | Другой мод (включая AddOns) использует тот же `AssemblyName`. Переименуйте свою сборку. |
| В сводке состояния ошибка загрузки библиотеки | DLL из списка `libraries` отсутствует или не является управляемой сборкой. |
| `FileNotFoundException` в логе | DLL, на которую есть ссылка, отсутствует в папке мода или не объявлена в `libraries`. Либо игровая DLL скопирована с `Private=true`, и две копии конфликтуют. |
| Исключение сразу после входа в мир | Исключение в обработчике события базы данных. Найдите пространство имён своего мода в трассировке стека в логе. |
| Эффекты накапливаются после возврата на титульный экран и повторного входа | Вы подписываетесь повторно внутри обработчика. Подписывайтесь только один раз, в `OnModLoaded`. |
