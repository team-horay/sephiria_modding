# การเผยแพร่บน Workshop

หน้านี้อธิบายวิธีอัปโหลดม็อดของคุณขึ้น Steam Workshop หลักการทำงานของระบบตรวจสอบ และวิธีที่ม็อดถูกซิงก์ระหว่างผู้เล่นในโหมดผู้เล่นหลายคน


## ก่อนอัปโหลด

- การอัปโหลดม็อดขึ้น Workshop จำเป็นต้องมีภาพตัวอย่าง (PNG หรือ JPG ขนาดไม่เกิน 1 MB) ตั้งค่าด้วย `info.preview` หรือวาง `thumbnail.png` ไว้ในโฟลเดอร์ม็อดของคุณ ดูรายละเอียดที่ [อ้างอิง metadata.json](metadata.md#preview)
- `info.title` ยาวได้ไม่เกิน 128 ตัวอักษร และ `info.description` ไม่เกิน 7999 ตัวอักษร หากคุณเขียนไว้หลายภาษา หน้า Workshop จะใช้เวอร์ชัน `en-US`
- ใส่หมวดหมู่ของ Workshop ใน `tags` ดูหมวดหมู่ที่ใช้ได้ที่ [อ้างอิง metadata.json](metadata.md)
- ทุกไฟล์ในโฟลเดอร์จะถูกตรวจสอบ ดังนั้นตรวจสอบให้แน่ใจว่าโฟลเดอร์ม็อดของคุณไม่มีสำเนา DLL ของเกม ไฟล์ `.pdb` หรือไฟล์ผลลัพธ์ชั่วคราวจากการบิลด์

## ขั้นตอนการเผยแพร่

1. เปิด Sephiria
2. เปิดแผง **Steam Workshop** บนหน้าจอไตเติล แล้วค้นหาม็อดที่คุณสร้าง
3. เลือกม็อดของคุณแล้วกด **อัปโหลดไปยัง Workshop**
4. สำหรับม็อดที่ไม่มีโค้ด การอัปโหลดขึ้น Workshop คือขั้นตอนสุดท้าย
5. สำหรับม็อดที่มีโค้ด (DLL) เมื่ออัปโหลดขึ้น Workshop เสร็จแล้ว ม็อดจะถูกส่งเข้า**ระบบตรวจสอบ**โดยอัตโนมัติพร้อมกับ ID ไอเทม Workshop
6. ไปที่หน้า Workshop ที่อัปโหลดแล้ว ทดสอบขั้นสุดท้าย เช่น สมัครรับม็อดด้วยตัวเอง แล้วเปลี่ยนการมองเห็นเป็น "สาธารณะ"

หากอัปโหลดขึ้น Workshop เสร็จแล้วแต่มีเพียงการส่งตรวจสอบที่ล้มเหลว (เช่น เนื่องจากข้อผิดพลาดของเครือข่าย) ให้กด **อัปโหลดไปยัง Workshop** อีกครั้งที่ม็อดเดิม หากเนื้อหาไม่เปลี่ยนแปลง ม็อดจะไม่ถูกอัปโหลดขึ้น Workshop ซ้ำ แต่จะส่งตรวจสอบใหม่เท่านั้น การส่งตรวจสอบต้องทำด้วยบัญชี Steam ที่สร้างไอเทม Workshop นั้น

## การตรวจสอบโค้ด

- ระบบตรวจสอบจะดีคอมไพล์ DLL และตรวจหาการสื่อสารผ่านเครือข่าย การเข้าถึงไฟล์ obfuscation และพฤติกรรมที่เป็นอันตราย การตรวจสอบผสมผสานการวิเคราะห์อัตโนมัติกับการตรวจโดยผู้ดูแล และเราเข้าใจดีว่าไม่มีระบบตรวจสอบใดจับความเสี่ยงได้ทั้งหมด ถึงกระนั้น เรามุ่งหวังที่จะลดการแพร่กระจายของม็อดที่เป็นอันตรายผ่านกระบวนการตรวจสอบนี้ ขอบคุณสำหรับความร่วมมือ
- ม็อดทุกตัวที่มีโค้ด (DLL) **ต้องส่งเข้าระบบตรวจสอบม็อดด้วย** โดยให้อัปโหลดผ่านปุ่ม **อัปโหลดไปยัง Workshop** ในเกมเสมอ
- ม็อดที่อัปโหลดขึ้น Workshop แล้วแต่ไม่ได้ส่งเข้าระบบตรวจสอบ โดยทั่วไปผู้เล่นจะรันไม่ได้
- ผู้เล่นที่ดาวน์โหลดม็อดจะตรวจดูสถานะการตรวจสอบของม็อดโดยใช้ ID ไอเทม Workshop ของม็อดและ DLL ที่ติดตั้งไว้
  - **ส่งแล้ว / อนุมัติแล้ว**: ม็อดจะทำงาน แม้การตรวจสอบยังไม่เสร็จก็ทำงานได้
  - **ยังไม่ส่ง / ถูกปฏิเสธ**: ม็อดจะไม่ทำงาน และจะแสดงเหตุผลในแผงม็อด
- หากพบปัญหาระหว่างการตรวจสอบ ม็อดอาจถูกปฏิเสธได้แม้จะเผยแพร่ไปแล้ว สำหรับม็อดที่ถูกปฏิเสธ คุณสามารถดูเหตุผลได้ด้วย **ดูเหตุผลที่ถูกปฏิเสธ** ในแผง DLL ที่ถูกปฏิเสธไม่สามารถเผยแพร่ซ้ำได้ทั้งอย่างนั้น ให้แก้ไขปัญหาแล้วอัปโหลดอีกครั้ง
- แม้ไม่มีโมดูล `dll` ม็อดก็ยังต้องถูกตรวจสอบหากมี `libraries` หรือมี DLL หรือ EXE ที่เปลี่ยนนามสกุลไฟล์
- ม็อดที่ต้องผ่านการตรวจสอบโค้ดต้องมีขนาดไม่เกิน 20 MB เมื่อบีบอัดโฟลเดอร์

### สาเหตุที่ไม่ผ่านการตรวจสอบ

|ข้อความ|สาเหตุ|
|---|---|
|ไม่มีประวัติการส่งในระบบตรวจสอบ|ม็อดถูกอัปโหลดขึ้น Workshop แล้วแต่ไม่ได้ส่งเข้าระบบตรวจสอบ ให้ส่งอีกครั้งด้วยปุ่ม **อัปโหลดไปยัง Workshop**|
|ระบบตรวจสอบปฏิเสธการอนุมัติม็อดนี้|ทีมงานปฏิเสธม็อดด้วยเหตุผลบางประการ โปรดตรวจดูเหตุผลที่ถูกปฏิเสธ|
|ไม่สามารถรับข้อมูลจากเซิร์ฟเวอร์ตรวจสอบได้|การเชื่อมต่ออินเทอร์เน็ตของผู้สมัครรับอาจขัดข้อง หรืออาจมีปัญหาที่เซิร์ฟเวอร์ตรวจสอบ|
|ม็อดนี้มาจากระบบตรวจสอบเดิม|เซิร์ฟเวอร์ตรวจสอบได้รับการอัปเกรดและข้อมูลการยืนยันเดิมของม็อดถูกรีเซ็ต ให้ส่งอีกครั้ง|
|ตรวจพบไฟล์ DLL ที่ไม่ได้รับอนุญาตในม็อด|หากชุดไฟล์ DLL ในม็อดเปลี่ยนไประหว่างที่ม็อดทำงาน การโหลดม็อดนั้นจะถูกจำกัด กล่าวคือ กรณีต่อไปนี้อาจละเมิดระบบตรวจสอบ: ม็อดดาวน์โหลด DLL จากภายนอกระหว่างทำงานแล้วโหลดแอสเซมบลี; ม็อดสร้างและรัน DLL ของตัวเองระหว่างทำงาน; ม็อดแตก DLL ที่บรรจุไว้ภายในด้วยรูปแบบการบีบอัดของตัวเองแล้วนำมาใช้|

## การมองเห็นและการเผยแพร่สู่สาธารณะ

- เมื่ออัปโหลดครั้งแรก การมองเห็นจะถูกตั้งเป็น `Unlisted`
- ก่อนเผยแพร่สู่สาธารณะ ให้สมัครรับม็อดด้วยตัวเอง ตรวจสอบว่าสำเนาที่ติดตั้งทำงานได้ถูกต้อง แล้วจึงเปลี่ยนเป็น "สาธารณะ"
- คุณสามารถแก้ไขคำอธิบายหน้า ภาพหน้าจอ คำอธิบายในภาษาอื่น ๆ และอื่น ๆ ได้จากหน้าไอเทม Steam Workshop

## การอัปเดตม็อดของคุณ

คุณสามารถอัปเดตม็อดได้ด้วยวิธีเดียวกับตอนเผยแพร่

- การอัปเดตที่เปลี่ยน DLL จะถูกส่งตรวจสอบใหม่โดยอัตโนมัติหลังอัปโหลดและต้องผ่านการตรวจสอบอีกครั้ง หากคุณไม่ได้เปลี่ยน DLL ใด ๆ สถานะการตรวจสอบจะยังคงเดิม
- อย่าเปลี่ยน `modId` ม็อดจะถูกถือว่าเป็นม็อดคนละตัว ซึ่งอาจทำให้ dependency และอื่น ๆ พังได้
- **เพิ่มเลข `version` ใน `metadata.json` ทุกครั้งที่อัปเดต** เวอร์ชันของม็อดจะถูกเปรียบเทียบเมื่อเข้าร่วมล็อบบี้ผู้เล่นหลายคน ดังนั้นหากเนื้อหาเปลี่ยนแต่เวอร์ชันไม่เปลี่ยน ผู้เล่นที่มีเนื้อหาม็อดต่างกันอาจเข้ามาอยู่ในเกมเดียวกันและพบปัญหา

## ตั๋วอัปโหลด

หลังจากอัปโหลดแล้ว `uploadticket.json` จะถูกเพิ่มลงในโฟลเดอร์ม็อดของคุณ ไฟล์นี้มี ID ไอเทม Workshop และข้อมูลการส่งตรวจสอบของคุณ ดังนั้น**อย่าลบ** หากคุณจัดการโฟลเดอร์ม็อดด้วย git การคอมมิตไฟล์นี้ด้วยจะปลอดภัยที่สุด หากคุณเปลี่ยนคอมพิวเตอร์หรือฟอร์แมตเครื่องใหม่ คุณจะต้องใช้ไฟล์นี้เพื่ออัปเดตไอเทม Workshop เดิมต่อไป หากไม่มีไฟล์นี้ เกมจะถือว่าโฟลเดอร์เป็นม็อดใหม่ที่ไม่เคยเผยแพร่มาก่อน

`mod-guard-manifest.json` และ `mod-guard.sig.json` ที่ระบบตรวจสอบใช้ก่อนเวอร์ชัน 1.1.1 ไม่ได้ใช้งานอีกต่อไปแล้ว แม้จะยังเหลืออยู่ก็จะไม่ถูกอัปโหลดขึ้น Workshop และคุณสามารถลบทิ้งได้

ดูวิธีกู้คืนไฟล์นี้หากสูญหายได้ที่ [คำถามที่พบบ่อย](faq.md)


## กฎของโหมดผู้เล่นหลายคน

### การตั้งค่าล็อบบี้ผู้เล่นหลายคน

เมื่อโฮสต์สร้างล็อบบี้ผู้เล่นหลายคน **รายการม็อดที่โฮสต์เปิดใช้งาน** จะถูกลงทะเบียนกับล็อบบี้

- ม็อดที่ตั้งค่า `installation` เป็น `host_only`: ผู้เข้าร่วมไม่จำเป็นต้องติดตั้ง จะแสดงในรายการเท่านั้น
- ม็อดที่ตั้งค่า `multiplayer.installation` เป็น `everyone` (หรือไม่ได้ประกาศ): ผู้เข้าร่วมต้องติดตั้งด้วย
- ม็อดชุดแต่งกายและม็อดข้อมูล: ผู้เข้าร่วมต้องติดตั้งด้วย

### การเข้าร่วม

หากการตั้งค่าม็อดปัจจุบันของผู้เล่นต่างจากของล็อบบี้ ผู้เล่นจะต้องทำตามขั้นตอนนี้: ดาวน์โหลด → เปิดใช้งาน → รีสตาร์ตเกมแล้วลองเข้าร่วมอีกครั้ง

### ม็อดทดสอบที่ติดตั้งใน WorkshopLocal

โหมดผู้เล่นหลายคนจะใช้ไม่ได้ในเกมที่โหลดม็อดในเครื่องจาก `WorkshopLocal/` ไว้ หากต้องการทดสอบโหมดผู้เล่นหลายคน ให้อัปโหลดม็อดขึ้น Workshop ล้างโฟลเดอร์ในเครื่อง แล้วใช้สำเนาที่สมัครรับแทน คุณสามารถสมัครรับผ่านลิงก์ได้แม้ไอเทมจะยังเป็น `Unlisted`
