# metadata.json

ไฟล์ `metadata.json` ที่รากของโฟลเดอร์ม็อดคือไฟล์หลักที่อธิบายทั้ง**ว่าม็อดของคุณคืออะไร**และ**ทำงานอย่างไร**


## โครงสร้างโดยรวม

```json
{
  "info": {
    "title": "New Artifact Pack",
    "description": "Adds 12 artifacts.",
    "preview": "thumbnail.png"
  },
  "mod": {
    "schemaVersion": 1,
    "modId": "yourname.artifact-pack",
    "version": "0.9.1",
    "author": "Your Name",
    "multiplayer": { "installation": "everyone" },
    "modules": [
      { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" },
      { "type": "localization", "path": "Localization" }
    ],
    "libraries": [
      "bin/Helper.dll"
    ],
    "dependencies": [
      { "modId": "someone.shared-runtime", "version": "2.5.3", "workshopId": "123456789" }
    ]
  },
  "tags": ["Item"]
}
```

ระดับบนสุดนิยามสามสิ่ง

| คีย์ | บทบาท | จำเป็น |
|---|---|---|
| `info` | ชื่อ คำอธิบาย และภาพตัวอย่างที่แสดงบน Steam Workshop และในแผงภายในเกม | จำเป็น |
| `tags` | แท็กของ Workshop | ไม่บังคับ |
| `mod` | วิธีการทำงานของม็อด | จำเป็น |

## info

### title

- ชื่อของม็อด หากเว้นว่าง จะใช้ `modId` เป็นชื่อแทน
- คุณสามารถใช้แมปภาษาเพื่อกำหนดชื่อม็อดสำหรับแต่ละภาษาได้
	- นอกจากภาษาของคุณเองแล้ว แนะนำให้เพิ่มภาษาอังกฤษด้วย
- รหัสภาษาที่รองรับ: `ko-KR`, `en-US`, `ja-JP`, `zh-CN`, `zh-TW`, `de-DE`, `fr-FR`, `es-ES`, `it-IT`, `pl-PL`, `pt-BR`, `ru-RU`, `sv-SE`, `th-TH`, `tr-TR`

```json
"info": {
  "title": { "en-US": "New Artifact Pack", "ko-KR": "새 아티팩트 팩" }
}
```

### description

- คำอธิบายของม็อด
- เช่นเดียวกับ `title` คุณสามารถกำหนดคำอธิบายแยกตามภาษาได้

```json
"info": {
  "description": { "en-US": "Adds 12 artifacts.", "ko-KR": "아티팩트 12종을 추가합니다." }
}
```

### preview

- จำเป็นต้องมีภาพตัวอย่างเพื่ออัปโหลดขึ้น Workshop (PNG หรือ JPG ขนาดไม่เกิน 1 MB)
- ใส่เส้นทางสัมพัทธ์ไปยังภาพตัวอย่าง
- หากละไว้ เกมจะค้นหา `thumbnail.png`, `preview.png`, `thumbnail.jpg` และ `preview.jpg` ในโฟลเดอร์รากตามลำดับ


## mod

### schemaVersion

- เวอร์ชันปัจจุบันคือ 1
- โปรดทราบว่าตัวเลขนี้อาจเพิ่มขึ้นในอนาคตหากมีการเปลี่ยนแปลงสำคัญในวิธีการทำงานของม็อด

### modId

- สตริงเฉพาะที่ใช้ระบุม็อดของคุณ ใช้ตัวอักษรภาษาอังกฤษตัวพิมพ์เล็ก ตัวเลข จุด ขีดกลาง และขีดล่าง ความยาวไม่เกิน 64 ตัวอักษร
- **เลือกชื่อที่ไม่ซ้ำใคร** หาก `modId` ของคุณซ้ำกับม็อดอื่น ม็อดจะทำงานไม่ถูกต้อง การใส่ชื่อผู้สร้างนำหน้าช่วยหลีกเลี่ยงการซ้ำกันได้มาก
(เช่น `horay.artifact-pack`)
- **อย่าเปลี่ยน `modId` หลังจากเผยแพร่แล้ว** ผู้อื่นสามารถสร้างม็อดลูกต่อยอดจากม็อดของคุณผ่าน `dependencies` ได้ และพวกเขาจะระบุม็อดแม่ด้วย `modId`


### version

- สตริงที่กำหนดเวอร์ชันของม็อด
- ค่านี้จะถูกนำไปเปรียบเทียบเมื่อม็อดอื่นต้องการเวอร์ชันที่ตรงกันทุกประการผ่าน `dependencies.version`
- **เพิ่มเลขเวอร์ชันทุกครั้งที่อัปเดตม็อด** เมื่อเข้าร่วมล็อบบี้ผู้เล่นหลายคน เกมจะตรวจสอบว่าโฮสต์และผู้เข้าร่วมมีเวอร์ชันม็อดตรงกัน หากคุณเปลี่ยนเนื้อหาแต่คงเวอร์ชันเดิม ผู้เล่นที่มีเนื้อหาม็อดต่างกันอาจเข้ามาอยู่ในล็อบบี้เดียวกัน ซึ่งอาจทำให้การซิงก์เนื้อหาล้มเหลวหรือเกมดำเนินต่อไม่ได้
- แนะนำให้ใช้รูปแบบ 1.0.0 เช่นเดียวกับที่เกมใช้

### author

บอกให้ทุกคนรู้ว่าคุณคือใคร!

### multiplayer / installation

กำหนดว่าผู้เล่นในเกมแบบผู้เล่นหลายคนจำเป็นต้องมีม็อดนี้ร่วมกันหรือไม่ ค่าที่ใช้ได้:

| ค่า | คำอธิบาย |
|---|---|
| `local_only` | มีผลเฉพาะหน้าจอและ UI ของคุณเอง (ม็อดแปลภาษาและม็อด UI อย่างง่ายอยู่ในกลุ่มนี้) |
| `everyone` | ทุกคนในห้องต้องเปิดใช้งานม็อดเดียวกัน (ม็อดใด ๆ ที่เพิ่มหรือเปลี่ยนเนื้อหาอยู่ในกลุ่มนี้) |
| `host_only` | เฉพาะโฮสต์ที่ต้องเปิดใช้งาน ฝั่งผู้เข้าร่วมคนอื่นทำงานได้โดยไม่ต้องเปลี่ยนแปลง (ม็อดผู้เล่นหลายคนที่มีผลเฉพาะการคำนวณฝั่งเซิร์ฟเวอร์อยู่ในกลุ่มนี้) |

หากคุณประกาศ `installation` เป็น `local_only` หรือ `host_only` แต่ม็อดของคุณแตะต้องเนื้อหาที่ผู้เข้าร่วมก็จำเป็นต้องมีด้วย (การลงทะเบียนไอเทมหรือยูนิตใหม่ ออบเจ็กต์เครือข่าย โค้ดที่ทำงานบนไคลเอนต์ของผู้เข้าร่วมด้วย) ผู้เล่นในล็อบบี้เดียวกันอาจกลายเป็นเล่นเกมคนละแบบ หรือการซิงก์เนื้อหาอาจล้มเหลวจนเกมดำเนินต่อตามปกติไม่ได้ โปรดตรวจสอบให้แน่ใจว่าม็อดของคุณทำอะไรจริง ๆ


### modules

- โมดูลคือสิ่งที่นิยามว่าม็อดของคุณทำอะไร จึงเป็น**ส่วนที่สำคัญที่สุด**
- โมดูลที่มีในปัจจุบันคือ `localization, dll, costume, data`
- ดังตัวอย่างด้านล่าง คุณสามารถผสมหลายโมดูลไว้ในแพ็กเกจเดียวได้
- หากมีโมดูลที่ไม่รู้จักแม้แต่ตัวเดียว ทั้งแพ็กเกจจะถูกทำเครื่องหมายว่า "ไม่รองรับ" และม็อดจะถูกข้ามระหว่างการโหลด

```json
"modules": [
  { "type": "localization", "path": "Localization" },
  { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" },
  { "type": "costume", "path": "Costumes" },
  { "type": "data", "path": "Packs", "consumer": "someone.shared-runtime" }
]
```

#### type: โมดูล localization

```json
"modules": [
  { "type": "localization", "path": "Localization" }
]
```

- โมดูล `localization` ใช้สำหรับม็อดที่มีไฟล์ภาษา
- ตั้งค่า `path` เป็นโฟลเดอร์ที่มีไฟล์ภาษา
- วาง**ไฟล์ JSON ที่ตั้งชื่อตามรหัสภาษา** เช่น `ko-KR.json` และ `en-US.json` ไว้ในโฟลเดอร์ `path` ดูรหัสภาษาและรูปแบบไฟล์ที่เกมใช้ได้ที่ [ม็อดแปลภาษา](localization-mods.md)

#### type: โมดูล dll

```json
"modules": [
  { "type": "dll", "path": "bin/ArtifactPack.dll", "entryClass": "ArtifactPack.Entry" }
]
```

- โมดูล `dll` ช่วยให้คุณเชื่อมต่อกับเกมด้วยโค้ด C#
- ตั้งค่า `path` เป็นเส้นทางของไฟล์ DLL
- ตั้งค่า `entryClass` เป็นชื่อเต็มของคลาสจุดเริ่มต้นใน DLL รวมถึง namespace เกมจะไม่ค้นหาจุดเริ่มต้นใน DLL ให้ คุณจึง**ต้องระบุเอง** (สำหรับคลาสซ้อน ให้ใช้ `Ns.Outer+Inner`)
- อย่าใช้ `entryClass` เดียวกันในสองโมดูลที่ต่างกัน
- ทำงานได้เฉพาะบิลด์ Mono เท่านั้น
- ดูรายละเอียดได้ที่ [ม็อด DLL](dll-mods.md)

#### type: โมดูล costume

```json
"modules": [
  { "type": "costume", "path": "Costumes" }
]
```

- ช่วยให้คุณสร้างชุดแต่งกายของคุณเองได้โดยไม่ต้องเขียนโค้ด C# เลย
- ตั้งค่า `path` เป็นโฟลเดอร์ที่มีไฟล์ชุดแต่งกายของคุณ
- ในโหมดผู้เล่นหลายคน ทุกคนต้องติดตั้งม็อดนี้
- ดูรายละเอียดได้ที่ [ม็อดชุดแต่งกาย](costume-mods.md)


#### type: โมดูล data

```json
"modules": [
  { "type": "data", "path": "Packs", "consumer": "someone.shared-runtime" }
]
```

- โมดูลข้อมูลอเนกประสงค์สำหรับม็อด โดยทั่วไปจะไม่ได้ใช้ ส่วนใหญ่ใช้สำหรับ dependency ระหว่างม็อด
- `consumer` ระบุว่าม็อดใดจะใช้โมดูลข้อมูลนี้ แต่โดยปกติจะละไว้ หากละไว้ ทุกม็อดที่อยู่ใน `dependencies` จะอ่านข้อมูลนี้ได้
- หากคุณมีม็อดแม่หลายตัวและข้อมูลมีไว้สำหรับม็อดใดม็อดหนึ่งเท่านั้น ให้ใส่ `modId` ของม็อดนั้นใน `consumer` ค่านั้นต้องอยู่ใน `dependencies` ด้วย

### libraries

```json
"libraries": [
  "bin/Helper.dll",
  { "path": "bin/Newtonsoft.Json.dll" }
]
```

- รายการแอสเซมบลีช่วยเหลือที่โมดูล `dll` ของคุณอ้างอิง
- เกมจะค้นหา (resolve) การอ้างอิงโดยใช้**เฉพาะไฟล์ที่ประกาศไว้ที่นี่**เท่านั้น เพียงวาง DLL ไว้ในโฟลเดอร์ไม่เพียงพอที่จะถูกค้นพบ
- แต่ละรายการอาจเป็นสตริงหรือออบเจ็กต์ `{ "path": "..." }` ก็ได้
- แต่ละรายการต้องลงท้ายด้วย `.dll` และจะทำงานไม่ถูกต้องหากซ้ำกับ DLL ใน `modules`
- ไลบรารีจะไม่ถูกถือว่าเป็นจุดเริ่มต้น แม้จะมีคลาส `WorkshopModBase` อยู่ข้างใน ก็จะไม่ถูกเรียก

### dependencies

```json
"dependencies": [
  { "modId": "someone.shared-runtime", "version": "2.5.3", "workshopId": "123456789" }
]
```

- หากม็อดแม่เป็นม็อดประเภท "สร้างเนื้อหา" ม็อดลูกอาจเพิ่มเนื้อหาใหม่ต่อยอดจากม็อดนั้นได้
- ในกรณีนั้น คุณสามารถประกาศ dependency กับม็อดอื่นผ่าน `dependencies`
- เมื่อระบุม็อดแม่แล้ว ม็อดของคุณจะไม่ถูกโหลดก่อนม็อดแม่นั้น
- หากม็อดแม่หายไป ถูกปิดใช้งาน หรือโหลดไม่สำเร็จ การโหลดม็อดลูกทั้งหมดของมันจะถูกยกเลิก
- dependency มีได้สามฟิลด์ดังนี้

| ฟิลด์ | จำเป็น | กฎ |
|---|---|---|
| `modId` | ใช่ | `modId` ของม็อดที่คุณต่อยอด |
| `version` | ไม่ | **ใช้เฉพาะเมื่อต้องการสตริงเวอร์ชันที่ตรงกันทุกประการเท่านั้น** หากเวอร์ชันต่างกัน การโหลดจะถูกข้าม ดังนั้นโดยทั่วไปการละไว้จะปลอดภัยกว่า |
| `workshopId` | ไม่ | ช่วยให้ผู้ใช้ค้นหาและสมัครรับม็อดที่จำเป็นได้ |


## tags

- หมวดหมู่ที่ใช้เมื่ออัปโหลดขึ้น Workshop
- ม็อดหนึ่งตัวมีได้หลายแท็ก (สำหรับม็อดรวมที่เพิ่มทั้งไอเทมและชุดแต่งกาย ให้ใช้ `"tags": ["Item", "Costume"]`)

| หมวดหมู่ | เนื้อหา |
|---|---|
| `Item` | ไอเทม (อาร์ติแฟกต์ แผ่นจารึก โพชั่น ฯลฯ) คอมโบ |
| `Costume` | ชุดแต่งกาย |
| `Weapon` | อาวุธ |
| `NPC` | นักเดินทาง พ่อค้า ฯลฯ |
| `Enemy` | ศัตรูใหม่ บอส ฯลฯ |
| `Gameplay` | การเปลี่ยนแปลงเกมเพลย์ |
| `QoL` | การปรับปรุง UI ความสะดวก และการเข้าถึง |
| `Library` | รันไทม์ เฟรมเวิร์ก แพ็กข้อมูล ฯลฯ ที่ม็อดอื่นพึ่งพา |
| `Localization` | การแปลภาษา |

## กฎของเส้นทาง
 
- เส้นทางใน `modules[].path`, `libraries` และ `info.preview` ใช้กฎเดียวกันทั้งหมด
- อนุญาตเฉพาะเส้นทางสัมพัทธ์จากโฟลเดอร์ม็อดเท่านั้น (เส้นทางสัมบูรณ์ อักษรไดรฟ์ และ `..` จะถูกปฏิเสธ)
- ใช้ `/` เป็นตัวคั่น
- เส้นทางที่ผ่าน symbolic link หรือ junction จะถูกปฏิเสธ
- **ตัวพิมพ์เล็ก-ใหญ่ต้องตรงกับชื่อจริงทุกประการ** บน Windows การเขียน `localization` ยังเปิดโฟลเดอร์ได้ แต่เกมจะปฏิเสธเพราะถือว่าต่างจาก `Localization` (กฎนี้ช่วยให้ทำงานเหมือนกันบน Steam Deck (Linux))
